When you start React, understanding the **project structure** is more important than memorizing every file. You need to know what each file does, which files you normally edit, and which files you should mostly leave alone.

I’ll explain a typical **React + Vite** project because that is the best structure for learning modern React.

A fresh project often looks like this:

```text
my-react-app/
│
├── node_modules/
├── public/
│
├── src/
│   ├── assets/
│   ├── App.css
│   ├── App.jsx
│   ├── index.css
│   └── main.jsx
│
├── .gitignore
├── eslint.config.js
├── index.html
├── package.json
├── package-lock.json
├── vite.config.js
└── README.md
```

Now let’s understand each part.

---

# 1. The root folder

```text
my-react-app/
```

This is your whole project.

Think of it like:

```text
Project Root
│
├── Application code
├── Dependencies
├── Configuration
└── Build setup
```

Everything belongs inside this folder.

---

# 2. `node_modules/`

```text
node_modules/
```

This contains installed packages.

For example:

```text
react
react-dom
vite
eslint
```

You usually do **not** edit anything inside `node_modules`.

It is generated automatically after:

```bash
npm install
```

Think of it as:

```text
node_modules
=
Downloaded libraries your project depends on
```

You also normally do not commit it to Git.

---

# 3. `public/`

```text
public/
```

This folder contains static files that should be served directly.

For example:

```text
public/
├── favicon.ico
├── robots.txt
└── logo.png
```

You can access them directly.

If you have:

```text
public/logo.png
```

you can use:

```jsx
<img src="/logo.png" alt="Logo" />
```

Notice:

```text
public/logo.png
```

becomes:

```text
/logo.png
```

in the browser.

---

# 4. `src/`

This is the most important folder.

```text
src/
```

Most of your React development happens here.

Think:

```text
src
=
Your application source code
```

A beginner project might have:

```text
src/
├── assets/
├── App.css
├── App.jsx
├── index.css
└── main.jsx
```

As the project grows, you will add more folders.

---

# 5. `main.jsx`

This is usually the **entry point** of your React application.

Example:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./index.css";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

This is a very important file to understand.

The flow is:

```text
index.html
    ↓
#root
    ↓
main.jsx
    ↓
<App />
    ↓
Your React application
```

The key line:

```jsx
createRoot(document.getElementById("root"))
```

finds this element:

```html
<div id="root"></div>
```

Then:

```jsx
.render(<App />)
```

tells React:

> Render my `App` component inside `#root`.

---

# 6. `App.jsx`

This is usually the main application component.

Example:

```jsx
function App() {
  return (
    <div>
      <h1>Hello React</h1>
    </div>
  );
}

export default App;
```

Then `main.jsx` imports it:

```jsx
import App from "./App.jsx";
```

Think:

```text
main.jsx
=
Starts React
```

```text
App.jsx
=
Main application component
```

A larger `App.jsx` might contain:

```jsx
function App() {
  return (
    <>
      <Header />
      <Hero />
      <Services />
      <Footer />
    </>
  );
}
```

---

# 7. `index.html`

This is the HTML page Vite uses.

Example:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta
      name="viewport"
      content="width=device-width, initial-scale=1.0"
    />
    <title>React App</title>
  </head>

  <body>
    <div id="root"></div>

    <script
      type="module"
      src="/src/main.jsx"
    ></script>
  </body>
</html>
```

The most important part is:

```html
<div id="root"></div>
```

React will mount your app inside this element.

And:

```html
<script type="module" src="/src/main.jsx"></script>
```

loads the React entry file.

So the chain is:

```text
index.html
   ↓
main.jsx
   ↓
App.jsx
   ↓
Components
```

Memorize that flow.

---

# 8. `index.css`

This usually contains global CSS.

Example:

```css
body {
  margin: 0;
  font-family: Arial, sans-serif;
}
```

This file affects the whole application.

For example:

```css
* {
  box-sizing: border-box;
}
```

or:

```css
body {
  background: #f5f5f5;
}
```

And `main.jsx` usually imports it:

```jsx
import "./index.css";
```

---

# 9. `App.css`

This often contains styles related to `App.jsx`.

Example:

```css
.container {
  max-width: 1200px;
  margin: auto;
}
```

Then:

```jsx
import "./App.css";
```

inside `App.jsx`.

For small projects this is okay.

In larger projects, you may instead organize CSS by component.

Example:

```text
components/
├── Header/
│   ├── Header.jsx
│   └── Header.css
```

---

# 10. `assets/`

```text
src/assets/
```

This is usually for files imported by JavaScript.

For example:

```text
src/assets/
├── logo.svg
├── hero.jpg
└── icons/
```

Then:

```jsx
import heroImage from "./assets/hero.jpg";

function Hero() {
  return <img src={heroImage} alt="Hero" />;
}
```

This is different from `public/`.

---

# `public` vs `src/assets`

This is a useful interview and practical concept.

## `public`

Use it when you want a static file available by direct URL.

```text
public/logo.png
```

Use:

```jsx
<img src="/logo.png" />
```

## `src/assets`

Use it when the file is part of your JavaScript module system.

```text
src/assets/logo.png
```

Use:

```jsx
import logo from "./assets/logo.png";

<img src={logo} />
```

Simple rule:

```text
public
=
Direct static file
```

```text
src/assets
=
Imported application asset
```

# 11. `package.json`

This describes your project.

Example:

```json
{
  "name": "my-react-app",
  "private": true,
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint .",
    "preview": "vite preview"
  },
  "dependencies": {
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "devDependencies": {
    "vite": "^7.0.0",
    "eslint": "^9.0.0"
  }
}
```

Important sections:

```text
scripts
dependencies
devDependencies
```

For example:

```bash
npm run dev
```

runs:

```json
"dev": "vite"
```

---

# 12. `package-lock.json`

This records the exact dependency versions npm resolved.

You usually:

```text
Keep it
Commit it
Do not manually edit it
```

It helps everyone on the team install consistent versions.

---

# 13. `.gitignore`

This tells Git which files or folders should not be committed.

Example:

```text
node_modules
dist
.env
```

This is important because you usually do not want Git tracking:

```text
node_modules/
build output
local environment secrets
```

---

# 14. `vite.config.js`

This is Vite's configuration file.

A basic version might look like:

```js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()]
});
```

As a beginner, you usually do not need to change this file much.

Later, it may contain:

```text
Aliases
Plugins
Dev server settings
Proxy configuration
Build settings
```

---

# 15. `eslint.config.js`

This contains ESLint configuration.

ESLint helps find code problems.

For example:

```js
const unused = "hello";
```

ESLint might warn that:

```text
unused
```

was declared but never used.

Think:

```text
ESLint
=
Code quality checker
```

It is not React itself.

---

# 16. `README.md`

This is project documentation.

Usually contains:

```text
Project description
Installation steps
Development instructions
Deployment instructions
Environment variables
```

For example:

```text
npm install
npm run dev
```

# A better project structure

Once your project grows, putting everything inside `src/` becomes messy.

You should start organizing it.

A common structure:

```text
src/
│
├── assets/
├── components/
├── pages/
├── layouts/
├── hooks/
├── services/
├── utils/
├── context/
├── styles/
│
├── App.jsx
└── main.jsx
```

Let's understand them.

---

# 17. `components/`

Reusable UI components.

Example:

```text
components/
├── Header.jsx
├── Footer.jsx
├── Button.jsx
├── ProductCard.jsx
└── Modal.jsx
```

Example:

```jsx
function Button({ children }) {
  return (
    <button>
      {children}
    </button>
  );
}

export default Button;
```

Use it:

```jsx
<Button>Buy Now</Button>
```

A component should usually have a clear responsibility.

---

# 18. `pages/`

Contains page-level components.

Example:

```text
pages/
├── Home.jsx
├── About.jsx
├── Contact.jsx
├── Login.jsx
└── Dashboard.jsx
```

These are different from reusable components.

For example:

```text
Button
=
Reusable component
```

```text
Home
=
Page
```

The Home page may contain many components:

```jsx
function Home() {
  return (
    <>
      <Hero />
      <Services />
      <Testimonials />
    </>
  );
}
```

---

# 19. `layouts/`

Layouts represent reusable page structures.

Example:

```text
layouts/
├── MainLayout.jsx
└── DashboardLayout.jsx
```

Example:

```jsx
function MainLayout({ children }) {
  return (
    <>
      <Header />

      <main>
        {children}
      </main>

      <Footer />
    </>
  );
}
```

Then many pages can share the same:

```text
Header
Footer
Navigation
Sidebar
```

---

# 20. `hooks/`

This contains custom React Hooks.

Example:

```text
hooks/
├── useAuth.js
├── useFetch.js
└── useLocalStorage.js
```

Example:

```js
function useAuth() {
  // authentication logic
}
```

Custom hooks normally begin with:

```text
use
```

such as:

```text
useAuth
useFetch
useWindowSize
```

---

# 21. `services/`

This commonly contains API-related code.

Example:

```text
services/
├── api.js
├── userService.js
└── productService.js
```

Instead of putting this everywhere:

```js
fetch("https://api.example.com/products")
```

you can create:

```js
export async function getProducts() {
  const response = await fetch(
    "https://api.example.com/products"
  );

  return response.json();
}
```

Then:

```jsx
import { getProducts } from "../services/productService";
```

This keeps components cleaner.

---

# 22. `utils/`

Utility functions.

Example:

```text
utils/
├── formatDate.js
├── formatPrice.js
└── validation.js
```

Example:

```js
export function formatPrice(price) {
  return `$${price.toFixed(2)}`;
}
```

Then:

```jsx
formatPrice(20);
```

returns:

```text
$20.00
```

These functions are usually not React-specific.

---

# 23. `context/`

Used when working with React Context.

Example:

```text
context/
├── AuthContext.jsx
└── ThemeContext.jsx
```

You might store:

```text
Logged-in user
Theme
Language
Shared application state
```

here.

You don't need to focus on this until you understand props and state well.

---

# 24. `styles/`

For shared styles.

Example:

```text
styles/
├── globals.css
├── variables.css
└── buttons.css
```

Whether you need this depends on your styling approach.

You might use:

```text
CSS
CSS Modules
Tailwind CSS
Styled Components
```

---

# Component folder structure

For larger projects, you may structure components like:

Or:

```text
components/
```

This keeps related files together.

```text
   ↓

   ↓
```

Example:

```jsx
function Home() {
  return (
    <>
      <Hero />
```

```jsx
function Hero() {
```

# Import paths

You will constantly use imports.

Example:

```jsx
import Header from "./components/Header/Header";
```

The `./` means:

```text
Start from the current folder
```

Example:

```text
src/
├── App.jsx
└── components/
    └── Header.jsx
```

Inside `App.jsx`:

```jsx
import Header from "./components/Header";
```

But if the file is inside:

```text
src/pages/Home.jsx
```

and Header is:

```text
src/components/Header.jsx
```

you may write:

```jsx
import Header from "../components/Header";
```

`../` means:

```text
Go up one folder
```

---

# Relative paths

Remember:

```text
./
=
Current folder
```

```text
../
=
Parent folder
```

Example:

```text
src/
├── components/
│   └── Header.jsx
│
└── pages/
    └── Home.jsx
```

From `Home.jsx`:

```jsx
import Header from "../components/Header";
```

Because:

```text
Home.jsx
↓
Go up from pages/
↓
src/
↓
components/
↓
Header.jsx
```

# Named export vs default export

Project structure becomes easier when you understand exports.

Default export:

```jsx
function Header() {
  return <header>Header</header>;
}

export default Header;
```

Import:

```jsx
import Header from "./Header";
```

Named export:

```jsx
export function Header() {
  return <header>Header</header>;
}
```

Import:

```jsx
import { Header } from "./Header";
```

The braces matter.

# Where should state live?

Do not organize a React project only by files.

Also think about ownership.

If only one component needs state:

```text
ProductCard
```

keep it there.

If multiple children need the same state:

```text
Parent
├── Child A
└── Child B
```

state may need to move to the parent.

As apps grow, shared state may live in:

```text
Context
State management library
Server-state library
```

But don't start there too early.

# Beginner mistakes

## Mistake 1: Putting everything in App.jsx

Bad:

```jsx
function App() {
  return (
    <>
      {/* 800 lines */}
    </>
  );
}
```

Better:

```jsx
function App() {
  return (
    <>
      <Header />
      <Hero />
      <Services />
      <Footer />
    </>
  );
}
```

---

## Mistake 2: Creating too many tiny components

This can also be bad.

You don't need:

```text
HeadingText.jsx
ParagraphText.jsx
SmallIcon.jsx
EverySingleDiv.jsx
```

A component should normally represent a meaningful reusable UI or responsibility.

---

## Mistake 3: Putting API calls everywhere

Avoid:

```text
Home.jsx → fetch
Header.jsx → fetch
ProductCard.jsx → fetch
Footer.jsx → fetch
```

where the logic becomes duplicated.

Instead, isolate reusable API logic where appropriate.

---

## Mistake 4: Organizing too early

You do not need this on day one:

```text
repositories/
adapters/
providers/
domain/
use-cases/
controllers/
factories/
```

for a small React exercise.

Start simple.

Let complexity justify structure.

---

# Common Interview Questions

### 1. What is `main.jsx`?

> `main.jsx` is typically the entry point of a Vite React application. It creates the React root and renders the main application component.

---

### 2. What is `App.jsx`?

> `App.jsx` is commonly the root application component where the main UI structure is composed.

---

### 3. What is the purpose of the `src` folder?

> The `src` folder contains the application's source code, including components, styles, assets, hooks, and other application logic.

---

### 4. What is `public` used for?

> The `public` directory stores static assets that are served directly and are not normally imported through the JavaScript module system.

---

### 5. What is `node_modules`?

> `node_modules` contains the packages installed for the project.

---

### 6. Should `node_modules` be committed to Git?

Usually no.

Dependencies are recreated using:

```bash
npm install
```

from:

```text
package.json
package-lock.json
```

---

### 7. What is `package.json`?

> It is the project manifest containing dependencies, scripts, metadata, and configuration information.

---

### 8. What is the difference between components and pages?

A good answer:

> Components are generally reusable pieces of UI, while pages represent complete application screens or routes composed from multiple components.

---

### 9. What is the role of `vite.config.js`?

> It contains configuration for Vite, such as plugins, aliases, development server settings, and build configuration.

---

# The mental model you should remember

Do not try to memorize every folder.

Remember this:

```text
index.html
     ↓
main.jsx
     ↓
App.jsx
     ↓
pages
     ↓
components
```

And separately:

```text
package.json
     ↓
npm
     ↓
node_modules
```

And:

```text
assets
=
Files used by your UI
```

For your next step, I would recommend building one small React project with only:

```text
App.jsx
components/
pages/
assets/
```

because once you physically create and import 4–5 components yourself, the project structure becomes much easier to understand than learning it only from diagrams.
