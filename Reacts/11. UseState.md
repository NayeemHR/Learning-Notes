`useState` is one of the most important React Hooks.

It lets a component **remember a value between renders** and update the UI when that value changes.

A simple definition is:

> **`useState` lets a React component store and update state.**

## 1. What is state?

State is data that belongs to a component and can change over time.

Examples:

```text
Counter value
Input text
Modal open/closed
Logged-in status
Selected tab
Cart items
Dark mode
```

Example:

```jsx
const [count, setCount] = useState(0);
```

Here:

```text
count
→ current state value

setCount
→ function used to update the state

0
→ initial state value
```

---

# 2. Basic `useState` example

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  function handleIncrease() {
    setCount(count + 1);
  }

  return (
    <div>
      <h1>{count}</h1>

      <button onClick={handleIncrease}>
        Increase
      </button>
    </div>
  );
}
```

Initially:

```text
count = 0
```

After clicking:

```text
count = 1
```

Then:

```text
count = 2
```

The important flow is:

```text
User clicks
   ↓
handleIncrease()
   ↓
setCount()
   ↓
React updates state
   ↓
Component re-renders
   ↓
UI shows new count
```

---

# 3. Why do we need `useState`?

You may ask:

> Why not use a normal variable?

Example:

```jsx
function Counter() {
  let count = 0;

  function handleClick() {
    count++;
    console.log(count);
  }

  return (
    <button onClick={handleClick}>
      {count}
    </button>
  );
}
```

The variable changes internally, but React does not know that the UI needs to update.

Changing:

```js
count++;
```

does not tell React:

> Render this component again.

With `useState`:

```jsx
setCount(count + 1);
```

React knows there is a state update.

That is the key difference.

---

# 4. Normal variable vs state

```text
Normal variable
→ React does not track it
→ changing it does not trigger rendering
```

```text
State
→ React tracks it
→ updating it can trigger rendering
```

So:

```js
let count = 0;
```

is not the same as:

```jsx
const [count, setCount] = useState(0);
```

---

# 5. Understanding the syntax

Look carefully:

```jsx
const [count, setCount] = useState(0);
```

This is JavaScript array destructuring.

`useState(0)` conceptually gives you something like:

```js
[countValue, updateFunction]
```

You destructure it:

```js
const [count, setCount] = ...
```

A simplified mental model:

```text
useState(0)

returns

[
  currentValue,
  updateFunction
]
```

So:

```jsx
const [count, setCount] = useState(0);
```

means:

```text
count
=
current value

setCount
=
function to request a new value
```

---

# 6. State setter naming convention

Usually:

```text
state name
→ count

setter
→ setCount
```

Examples:

```jsx
const [name, setName] = useState("");

const [open, setOpen] = useState(false);

const [users, setUsers] = useState([]);

const [user, setUser] = useState(null);
```

Pattern:

```text
value
setValue
```

# 7. Different state types

`useState` can hold many types of values.

## Number

```jsx
const [count, setCount] = useState(0);
```

## String

```jsx
const [name, setName] = useState("");
```

## Boolean

```jsx
const [isOpen, setIsOpen] = useState(false);
```

## Array

```jsx
const [users, setUsers] = useState([]);
```

## Object

```jsx
const [user, setUser] = useState({
  name: "",
  email: ""
});
```

## Null

```jsx

```

# 8. String state example

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  return (
    <div>
      <input
        value={name}
        onChange={e => setName(e.target.value)}
      />

      <p>Hello {name}</p>
    </div>
  );
}
```

Flow:

```text
User types
   ↓
onChange
   ↓
e.target.value
   ↓
setName()
   ↓
state changes
   ↓
component re-renders
   ↓
new text appears
```

# 9. Boolean state example

Very common for modals, menus, and dropdowns.

```jsx
import { useState } from "react";

function App() {
  const [isOpen, setIsOpen] = useState(false);

  function handleToggle() {
    setIsOpen(!isOpen);
  }

  return (
    <div>
      <button onClick={handleToggle}>
        Toggle
      </button>

      {isOpen && (
        <p>Menu is open</p>
      )}
    </div>
  );
}
```

Initially:

```text
isOpen = false
```

Click:

```text
isOpen = true
```

Click again:

```text
isOpen = false
```

---

# 10. Better toggle pattern

Instead of:

```jsx
setIsOpen(!isOpen);
```

you will often see:

```jsx
setIsOpen(prevIsOpen => !prevIsOpen);
```

Why?

Because the new state depends on the previous state.

This is called a **functional state update**.

Think:

```text
previous value
   ↓
calculate next value
   ↓
return new value
```

---

# 11. Functional updater

Suppose:

```jsx
const [count, setCount] = useState(0);
```

Instead of:

```jsx
setCount(count + 1);
```

you can write:

```jsx
setCount(prevCount => prevCount + 1);
```

This is especially important when the next state depends on previous state.

Example:

```jsx
function handleClick() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
}
```

This correctly applies three updates.

Conceptually:

```text
0
↓
1
↓
2
↓
3
```

---

# 12. Why this can be wrong

Consider:

```jsx
function handleClick() {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
}
```

All three lines may be based on the same render's `count`.

If:

```text
count = 0
```

they can all effectively request:

```text
1
```

So do not assume the result will be `3`.

When state depends on previous state, prefer:

```jsx
setCount(prev => prev + 1);
```

---

# 13. State updates are not immediate variable assignments

This is important.

Suppose:

```jsx
function handleClick() {
  console.log(count);

  setCount(count + 1);

  console.log(count);
}
```

If `count` was `0`, you may see:

```text
0
0
```

Why?

Because:

```jsx
setCount(...)
```

does not change the `count` variable inside the currently running render.

Instead, it schedules a new render with the new state.

Mental model:

```text
Current render
count = 0

setCount(1)
   ↓
request next render

Current handler still sees
count = 0

Next render
count = 1
```

---

# 14. State behaves like a snapshot

This is one of the best ways to understand React state.

Each render gets a snapshot of state.

Example:

```text
Render 1
count = 0
```

Then:

```jsx
setCount(1);
```

React creates another render:

```text
Render 2
count = 1
```

The old render's value doesn't magically change.

So think:

> **State is a snapshot for each render.**

---

# 15. Array state

Suppose:

```jsx
const [users, setUsers] = useState([
  { id: 1, name: "John" },
  { id: 2, name: "Sarah" }
]);
```

To add:

```jsx
const newUser = {
  id: 3,
  name: "David"
};

setUsers([
  ...users,
  newUser
]);
```

Avoid:

```js
users.push(newUser);
```

Why?

Because React state should generally be treated as immutable.

---

# 16. Why immutability matters

React compares references.

If you mutate the same array:

```js
users.push(newUser);
```

you are changing the existing array.

Instead:

```js
const newUsers = [
  ...users,
  newUser
];
```

creates a new array.

Then:

```jsx
setUsers(newUsers);
```

React gets a new reference.

This makes updates predictable.

---

# 17. Delete from array state

Use `filter()`:

```jsx
function handleDelete(id) {
  setUsers(
    users.filter(user => user.id !== id)
  );
}
```

Flow:

```text
Old array
   ↓
filter()
   ↓
New array
   ↓
setUsers()
```

---

# 18. Update an array item

Use `map()`:

```jsx
function activateUser(id) {
  setUsers(
    users.map(user =>
      user.id === id
        ? { ...user, active: true }
        : user
    )
  );
}
```

You create a new object for the changed item.

---

# 19. Object state

Example:

```jsx
const [user, setUser] = useState({
  name: "John",
  age: 25
});
```

Suppose you only want to change `name`.

Do not do:

```jsx
setUser({
  name: "Sarah"
});
```

because that replaces the whole object.

You would lose:

```text
age
```

Instead:

```jsx
setUser({
  ...user,
  name: "Sarah"
});
```

Now:

```text
Old

{
  name: "John",
  age: 25
}
```

becomes:

```text
New

{
  name: "Sarah",
  age: 25
}
```

---

# 20. Object state with forms

Example:

```jsx
import { useState } from "react";

function App() {
  const [form, setForm] = useState({
    name: "",
    email: ""
  });

  function handleNameChange(e) {
    setForm({
      ...form,
      name: e.target.value
    });
  }

  function handleEmailChange(e) {
    setForm({
      ...form,
      email: e.target.value
    });
  }

  return (
    <div>
      <input
        value={form.name}
        onChange={handleNameChange}
      />

      <input
        value={form.email}
        onChange={handleEmailChange}
      />

      <p>{form.name}</p>
      <p>{form.email}</p>
    </div>
  );
}
```

---

# 21. Dynamic object update

You can make the form handler reusable.

```jsx
function handleChange(e) {
  const { name, value } = e.target;

  setForm({
    ...form,
    [name]: value
  });
}
```

Inputs:

```jsx
<input
  name="name"
  value={form.name}
  onChange={handleChange}
/>

<input
  name="email"
  value={form.email}
  onChange={handleChange}
/>
```

The syntax:

```js
[name]: value
```

means:

> Use the value of the `name` variable as the object property name.

---

# 22. State should be minimal

Suppose you have:

```jsx
const [firstName, setFirstName] = useState("John");
const [lastName, setLastName] = useState("Doe");
```

You probably don't need:

```jsx
const [fullName, setFullName] = useState("John Doe");
```

because:

```js
const fullName = firstName + " " + lastName;
```

can be calculated during rendering.

Avoid storing derived data unnecessarily.

A good rule:

> Store the minimum state needed, derive the rest.

---

# 23. Bad derived state example

Avoid:

```jsx
const [price, setPrice] = useState(100);
const [quantity, setQuantity] = useState(2);
const [total, setTotal] = useState(200);
```

Now you have to keep `total` synchronized manually.

Better:

```jsx
const [price, setPrice] = useState(100);
const [quantity, setQuantity] = useState(2);

const total = price * quantity;
```

This reduces bugs.

---

# 24. Multiple `useState` calls

A component can have multiple states.

```jsx
function Profile() {
  const [name, setName] = useState("");
  const [age, setAge] = useState(0);
  const [isEditing, setIsEditing] = useState(false);
}
```

That is completely normal.

You do not need to put everything into one object.

---

# 25. One object or multiple states?

You might ask:

Should I use:

```jsx
const [name, setName] = useState("");
const [email, setEmail] = useState("");
```

or:

```jsx
const [form, setForm] = useState({
  name: "",
  email: ""
});
```

Both are valid.

Use separate state when values are mostly independent.

Use an object when values logically belong together.

For a form, an object can be convenient.

# 26. Initial state

This:

```jsx
useState(0)
```

means initial state is:

```text
0
```

This:

```jsx
useState("")
```

means:

```text
empty string
```

This:

```jsx
useState(false)
```

means:

```text
false
```

Initial state is used when the component first mounts.

# 27. Lazy initial state

Sometimes creating the initial state is expensive.

Instead of:

```jsx
const [data, setData] = useState(
  expensiveCalculation()
);
```

you can write:

```jsx
const [data, setData] = useState(() => {
  return expensiveCalculation();
});
```

This lets React call the initializer when setting up the initial state rather than recalculating it on every render expression evaluation.

For beginners, you don't need this often, but it is useful to know.

# 28. Rules of Hooks

`useState` is a Hook.

Hooks have important rules.

Call Hooks at the top level of your component.

Correct:

```jsx
function App() {
  const [count, setCount] = useState(0);

  return <div>{count}</div>;
}
```

Avoid:

```jsx
function App() {
  if (loggedIn) {
    const [count, setCount] = useState(0);
  }
}
```

Also avoid:

```jsx
for (...) {
  const [count, setCount] = useState(0);
}
```

Why?

React relies on Hooks being called in a consistent order between renders.

---

# 29. Why Hook order matters

Imagine:

```jsx
const [name, setName] = useState("");
const [age, setAge] = useState(0);
const [open, setOpen] = useState(false);
```

React can conceptually associate them by call order:

```text
Hook 1 → name
Hook 2 → age
Hook 3 → open
```

If you conditionally skip Hook 2:

```text
Render 1

Hook 1
Hook 2
Hook 3
```

then later:

```text
Render 2

Hook 1
Hook 3
```

React's association would break.

That is why Hooks should remain at the top level.

---

# 30. `useState` must be inside React components or custom Hooks

Valid:

```jsx
function Counter() {
  const [count, setCount] = useState(0);
}
```

Valid custom Hook:

```jsx
function useCounter() {
  const [count, setCount] = useState(0);

  return [count, setCount];
}
```

Not valid at random module scope:

```jsx
const [count, setCount] = useState(0);
```

outside a component/custom Hook.

---

# 31. State belongs to a component position

Consider:

```jsx
function App() {
  return (
    <>
      <Counter />
      <Counter />
    </>
  );
}
```

Each `Counter` gets independent state.

Conceptually:

```text
Counter A
count = 0

Counter B
count = 0
```

Click Counter A:

```text
Counter A
count = 1

Counter B
count = 0
```

Even though both use the same component definition.

React stores state based on component identity/position in the tree.

---

# 32. Keys can reset state

Suppose:

```jsx
<UserProfile key="john" />
```

then change to:

```jsx
<UserProfile key="sarah" />
```

React considers the component identity different.

Its state can reset.

This connects `useState` to what you learned about reconciliation and keys.

# 33. State lifting

Suppose two child components need the same state.

Instead of:

```text
Child A → own state
Child B → own unrelated copy
```

you can move state to the parent:

```text
        Parent
        state
       /     \
      ↓       ↓
 Child A   Child B
```

Example:

```jsx
function App() {
  const [count, setCount] = useState(0);

  return (
    <>
      <Display count={count} />
      <Button setCount={setCount} />
    </>
  );
}
```

This is called:

> **Lifting state up**

---

# 34. A full realistic example

```jsx
import { useState } from "react";

function App() {
  const [products, setProducts] = useState([
    {
      id: 1,
      name: "Laptop",
      price: 1200
    },
    {
      id: 2,
      name: "Phone",
      price: 800
    }
  ]);

  function handleDelete(id) {
    setProducts(
      products.filter(product => product.id !== id)
    );
  }

  return (
    <div>
      <h1>Products</h1>

      {products.map(product => (
        <div key={product.id}>
          <h2>{product.name}</h2>
          <p>${product.price}</p>

          <button
            onClick={() => handleDelete(product.id)}
          >
            Delete
          </button>
        </div>
      ))}
    </div>
  );
}

export default App;
```

This combines:

```text
useState
Arrays
map()
Event handlers
filter()
Keys
Re-rendering
```

# 35. What exactly happens after `setState`?

Suppose:

```jsx
setCount(prev => prev + 1);
```

A simplified flow:

```text
State update requested
      ↓
React schedules work
      ↓
Component renders again
      ↓
New state value is available
      ↓
JSX is recalculated
      ↓
Reconciliation
      ↓
Necessary DOM changes committed
```

This connects directly to React Fiber and reconciliation.

---

# 36. Does `useState` cause a full page reload?

No.

It causes React to re-render the relevant component tree.

The browser page itself does not reload.

So:

```text
useState update
≠
page refresh
```

# 37. Common beginner mistakes

## Mistake 1: Changing state directly

Wrong:

```js
count = count + 1;
```

Correct:

```jsx
setCount(count + 1);
```

---

## Mistake 2: Mutating arrays

Wrong:

```js
users.push(newUser);
```

Better:

```jsx
setUsers([
  ...users,
  newUser
]);
```

---

## Mistake 3: Mutating objects

Wrong:

```js
user.name = "Sarah";
```

Better:

```jsx
setUser({
  ...user,
  name: "Sarah"
});
```

---

## Mistake 4: Expecting immediate state change

Wrong assumption:

```jsx
setCount(count + 1);

console.log(count);
```

and expecting `count` to already contain the next render's value.

State is a render snapshot.

---

## Mistake 5: Calling Hooks conditionally

Avoid:

```jsx
if (active) {
  const [count, setCount] = useState(0);
}
```

Hooks must be called consistently at the top level.

# Common Interview Questions

### 1. What is `useState`?

A strong answer:

> `useState` is a React Hook that allows function components to store state and request re-renders when that state changes.

### 2. What does `useState` return?

> It returns an array containing the current state value and a state updater function.

Example:

```jsx
const [count, setCount] = useState(0);
```

### 3. Does calling the setter change state immediately?

> It schedules a state update. The current render continues to see its existing state snapshot, and the updated value becomes available in a subsequent render.

### 4. Why shouldn't we mutate state directly?

> React state should be treated as immutable because updates rely on predictable value/reference changes and React's rendering model.

### 5. When should we use a functional state update?

When the next state depends on the previous state.

Example:

```jsx
setCount(prev => prev + 1);
```

### 6. Can `useState` store objects and arrays?

Yes.

```jsx
useState({})
```

```jsx
useState([])
```

But updates should create new objects/arrays instead of mutating the existing ones.

### 7. What causes a component to re-render?

A state update can cause React to schedule a re-render.

Other causes include parent rendering and context changes.

### 8. Can we call `useState` inside an `if` statement?

No.

Hooks must be called at the top level so React can preserve consistent Hook ordering.

### 9. What is state lifting?

> Moving state to the nearest common parent so multiple child components can share the same source of truth.

### 10. State vs normal variable?

> A normal variable is recreated or changed without React tracking it, while state is preserved between renders and updating it can cause React to render again.

## The mental model to remember

Think:

```text
useState(initialValue)
        ↓
[currentValue, setter]
```

Then:

```text
Current State
     ↓
Render UI
     ↓
User Action
     ↓
Setter Function
     ↓
New State
     ↓
Re-render
     ↓
Updated UI
```

And memorize these four patterns:

```jsx
const [count, setCount] = useState(0);
```

```jsx
setCount(prev => prev + 1);
```

```jsx
setItems([...items, newItem]);
```

```jsx
setUser({
  ...user,
  name: "John"
});
```

If you fully understand those four patterns, you have a strong foundation in `useState`.
