Dynamic rendering from an array is one of the most important React patterns.

The core idea is:

> **You store data in an array, then use JavaScript's `map()` method to generate React elements from that data.**

If you understand `map()`, `key`, props, and components, you can render product lists, users, blog posts, menus, cards, tables, and many other UI patterns.

# 1. Start with a normal JavaScript array

Suppose we have:

```js
const names = ["John", "Sarah", "David"];
```

In normal JavaScript, you could loop through it:

```js
names.forEach(name => {
  console.log(name);
});
```

Output:

```text
John
Sarah
David
```

But in React, when we want to **create UI from an array**, we normally use:

```js
map()
```

because `map()` returns a new array.

---

# 2. Basic dynamic rendering with `map()`

Example:

```jsx
function App() {
  const names = ["John", "Sarah", "David"];

  return (
    <div>
      {names.map(name => (
        <p>{name}</p>
      ))}
    </div>
  );
}
```

React generates conceptually:

```html
<div>
  <p>John</p>
  <p>Sarah</p>
  <p>David</p>
</div>
```

The important part is:

```jsx
{names.map(name => (
  <p>{name}</p>
))}
```

Remember:

```text
Array
  ↓
map()
  ↓
React elements
  ↓
UI
```

# 3. Why are `{}` used?

Inside JSX:

```jsx
<div>
  {JavaScript goes here}
</div>
```

So:

```jsx
{names.map(...)}
```

means:

> Execute this JavaScript expression and render its result.

For example:

```jsx
const numbers = [1, 2, 3];

return (
  <div>
    {numbers.map(number => (
      <p>{number}</p>
    ))}
  </div>
);
```

# 4. Understand `map()` before React

This is important because `map()` is JavaScript, not React.

Normal JavaScript:

```js
const numbers = [1, 2, 3];

const doubled = numbers.map(number => {
  return number * 2;
});

console.log(doubled);
```

Result:

```js
[2, 4, 6]
```

So:

```text
map()
=
Take each item
↓
Transform it
↓
Return a new array
```

React uses exactly this idea.

Instead of transforming:

```text
1 → 2
```

you transform:

```text
John
↓
<p>John</p>
```

Conceptually:

```text
Apple
↓
<li>Apple</li>

Banana
↓
<li>Banana</li>

Mango
↓
<li>Mango</li>
```

# 6. The `key` problem

If you write:

```jsx
{fruits.map(fruit => (
  <li>{fruit}</li>
))}
```

React will usually warn you:

```text
Each child in a list should have a unique "key" prop
```

You should add a key:

```jsx
{fruits.map(fruit => (
  <li key={fruit}>
    {fruit}
  </li>
))}
```

So:

```jsx
const fruits = ["Apple", "Banana", "Mango"];

function App() {
  return (
    <ul>
      {fruits.map(fruit => (
        <li key={fruit}>
          {fruit}
        </li>
      ))}
    </ul>
  );
}
```

---

# 7. What is a `key`?

A key helps React identify each item in a rendered list.

React needs to know:

```text
Which item is new?
Which item was removed?
Which item moved?
Which item stayed the same?
```

Suppose:

```text
Before

John
Sarah
David
```

Then:

```text
After

John
Michael
Sarah
David
```

With stable keys, React can understand:

```text
John → same
Michael → new
Sarah → same
David → same
```

This helps reconciliation.

---

# 8. Best key: unique ID

The best key is usually a stable ID from your data.

Example:

```js
const users = [
  {
    id: 1,
    name: "John"
  },
  {
    id: 2,
    name: "Sarah"
  },
  {
    id: 3,
    name: "David"
  }
];
```

Render:

```jsx
function App() {
  return (
    <div>
      {users.map(user => (
        <p key={user.id}>
          {user.name}
        </p>
      ))}
    </div>
  );
}
```

Use:

```jsx
key={user.id}
```

This is the preferred pattern.

Real applications usually use arrays of objects rather than simple strings.

Example:

```js
const products = [
  {
    id: 1,
    name: "Laptop",

  {
    id: 2,
    name: "Phone",
    price: 800
  },
  {
    id: 3,
    name: "Tablet",
    price: 500
```

```jsx
function App() {

          <h2>{product.name}</h2>
```

Output conceptually:

```text

Phone
$800

Tablet
$500
```

# 10. Better approach: create a component

Instead of putting all markup inside `map()`:

```jsx
{products.map(product => (
  <div key={product.id}>
    <h2>{product.name}</h2>
    <p>${product.price}</p>
  </div>
))}
```

create:

```jsx
function ProductCard({ product }) {
  return (
    <div>
      <h2>{product.name}</h2>
      <p>${product.price}</p>
    </div>
  );
}
```

Then:

```jsx
function App() {
  const products = [
    {
      id: 1,
      name: "Laptop",
      price: 1200
    },
    {
      id: 2,
      name: "Phone",
      price: 800
    }
  ];

  return (
    <div>
      {products.map(product => (
        <ProductCard
          key={product.id}
          product={product}
        />
      ))}
    </div>
  );
}
```

This is much closer to real React development.

# 11. Important: where should the key go?

Suppose:

```jsx
products.map(product => (
  <ProductCard product={product} />
))
```

The `key` should be on the element directly returned by `map()`:

```jsx
products.map(product => (
  <ProductCard
    key={product.id}
    product={product}
  />
))
```

Not necessarily inside `ProductCard`.

Wrong pattern:

```jsx
function ProductCard({ product }) {
  return (
    <div key={product.id}>
      {product.name}
    </div>
  );
}
```

if `ProductCard` itself is the list item React is trying to identify.

The key belongs here:

```jsx
<ProductCard key={product.id} />
```

# 12. `map()` callback parameters

`map()` can give you more than the current item.

```js
array.map((item, index) => {
  // ...
});
```

Example:

```jsx
const names = ["John", "Sarah", "David"];

function App() {
  return (
    <div>
      {names.map((name, index) => (
        <p key={name}>
          {index + 1}. {name}
        </p>
      ))}
    </div>
  );
}
```

Output:

```text
1. John
2. Sarah
3. David
```

Here:

```text
name
=
current item
```

```text
index
=
current position
```

# 13. Should you use array index as key?

You may see:

```jsx
{users.map((user, index) => (
  <User key={index} />
))}
```

This works technically, but it is often not the best choice.

Why?

Imagine:

```text
Index 0 → John
Index 1 → Sarah
Index 2 → David
```

Then you add Michael at the beginning:

```text
Index 0 → Michael
Index 1 → John
Index 2 → Sarah
Index 3 → David
```

Now the keys changed for the existing logical items.

That can cause problems with:

```text
Inputs
Checkboxes
Local component state
Animations
Editable rows
Reordered lists
```

Prefer:

```jsx
key={user.id}
```

---

# 14. When is index as a key acceptable?

It can be acceptable when the list is truly static:

```text
Never reordered
Never deleted
Never inserted
No item-specific component state
```

For example:

```jsx
const steps = [
  "Install Node",
  "Create Project",
  "Run Development Server"
];
```

But even then, if you have stable unique data, prefer that.

---

# 15. Never use `Math.random()` as a key

Avoid:

```jsx
<ProductCard key={Math.random()} />
```

Why?

Every render produces a new key.

React thinks:

```text
Old component
≠
New component
```

So React may recreate components unnecessarily and reset their state.

Bad:

```jsx
key={Math.random()}
```

Better:

```jsx
key={product.id}
```

# 16. Rendering with destructuring

Instead of:

```jsx
products.map(product => (
  <div key={product.id}>
    <h2>{product.name}</h2>
    <p>{product.price}</p>
  </div>
))
```

you can destructure:

```jsx
products.map(({ id, name, price }) => (
  <div key={id}>
    <h2>{name}</h2>
    <p>${price}</p>
  </div>
))
```

Both are valid.

For beginners, I recommend starting with:

```jsx
product.name
product.price
```

because it is easier to follow.

# 18. Filtering before rendering

Suppose you only want products that are in stock.

Use:

```js
filter()
```

then:

```js
map()
```

Example:

```jsx
const products = [
  { id: 1, name: "Laptop", inStock: true },
  { id: 2, name: "Phone", inStock: false },
  { id: 3, name: "Tablet", inStock: true }
];

function App() {
  return (
    <div>
      {products
        .filter(product => product.inStock)
        .map(product => (
          <p key={product.id}>
            {product.name}
          </p>
        ))}
    </div>
  );
}
```

Flow:

```text
products
   ↓
filter()
   ↓
only matching products
   ↓
map()
   ↓
React elements
```

This combination is extremely common.

# 19. Search example

Suppose:

```jsx
const [search, setSearch] = useState("");
```

and:

```js
const products = [
  { id: 1, name: "Laptop" },
  { id: 2, name: "Phone" },
  { id: 3, name: "Tablet" }
];
```

You can write:

```jsx
const filteredProducts = products.filter(product =>
  product.name
    .toLowerCase()
    .includes(search.toLowerCase())
);
```

Then:

```jsx
{filteredProducts.map(product => (
  <ProductCard
    key={product.id}
    product={product}
  />
))}
```

Now:

```text
User types
   ↓
search state changes
   ↓
filter runs
   ↓
map runs
   ↓
matching UI renders
```

That is the basis of many React search interfaces.

# 20. Sorting before rendering

You can also sort data.

Example:

```jsx
const sortedProducts = [...products].sort(
  (a, b) => a.price - b.price
);
```

Then:

```jsx
{sortedProducts.map(product => (
  <ProductCard
    key={product.id}
    product={product}
  />
))}
```

Notice:

```js
[...products]
```

Why?

Because JavaScript's `sort()` mutates the original array.

In React, especially with state, you should generally avoid mutating existing data.

Better:

```js
[...products].sort(...)
```

than:

```js
products.sort(...)
```

when `products` is state or props.

# 21. Rendering an empty array

Suppose:

```js
const products = [];
```

Then:

```jsx
products.map(...)
```

returns an empty array.

React simply renders nothing.

But a better UI might show:

```text
No products found
```

Example:

```jsx
function ProductList({ products }) {
  if (products.length === 0) {
    return <p>No products found.</p>;
  }

  return (
    <div>
      {products.map(product => (
        <ProductCard
          key={product.id}
          product={product}
        />
      ))}
    </div>
  );
}
```

This is a good real-world pattern.

---

# 22. Conditional list rendering

Another approach:

```jsx
{products.length > 0 ? (
  products.map(product => (
    <ProductCard
      key={product.id}
      product={product}
    />
  ))
) : (
  <p>No products found.</p>
)}
```

Both approaches are valid.

I usually prefer early returns when the component becomes more complex.

# 23. Dynamic list from state

Now let's make the array change dynamically.

```jsx
import { useState } from "react";

function App() {
  const [users, setUsers] = useState([
    { id: 1, name: "John" },
    { id: 2, name: "Sarah" }
  ]);

  return (
    <div>
      {users.map(user => (
        <p key={user.id}>
          {user.name}
        </p>
      ))}
    </div>
  );
}
```

Now `users` is state.

If we update the array:

```jsx
setUsers([
  ...users,
  {
    id: 3,
    name: "David"
  }
]);
```

React rerenders the list.

Flow:

```text
users state
   ↓
map()
   ↓
UI

setUsers()
   ↓
new array
   ↓
component rerenders
   ↓
map() runs again
   ↓
new UI
```

# 24. Add an item dynamically

Example:

```jsx
import { useState } from "react";

function App() {
  const [users, setUsers] = useState([
    { id: 1, name: "John" }
  ]);

  function addUser() {
    const newUser = {
      id: Date.now(),
      name: "Sarah"
    };

    setUsers([
      ...users,
      newUser
    ]);
  }

  return (
    <div>
      <button onClick={addUser}>
        Add User
      </button>

      {users.map(user => (
        <p key={user.id}>
          {user.name}
        </p>
      ))}
    </div>
  );
}
```

Notice:

```js
setUsers([
  ...users,
  newUser
]);
```

We create a **new array**.

We do not do:

```js
users.push(newUser);
```

and expect React state handling to work correctly.

# 25. Remove an item dynamically

Use `filter()`.

```jsx
function removeUser(id) {
  setUsers(
    users.filter(user => user.id !== id)
  );
}
```

Full usage:

```jsx
{users.map(user => (
  <div key={user.id}>
    <span>{user.name}</span>

    <button
      onClick={() => removeUser(user.id)}
    >
      Delete
    </button>
  </div>
))}
```

Flow:

```text
Click Delete
   ↓
removeUser(id)
   ↓
filter()
   ↓
new array without that user
   ↓
setUsers()
   ↓
React rerenders
```

This is a pattern you will use constantly.

# 26. Update an item dynamically

Suppose:

```js
const users = [
  { id: 1, name: "John", active: false },
  { id: 2, name: "Sarah", active: true }
];
```

You can update one user with `map()`:

```jsx
function activateUser(id) {
  setUsers(
    users.map(user =>
      user.id === id
        ? { ...user, active: true }
        : user
    )
  );
}
```

Understand this carefully.

For every user:

```text
Is this the target user?
        ↓
       Yes
        ↓
create updated object

       No
        ↓
return original user
```

So `map()` is not only useful for rendering.

It is also useful for updating arrays immutably.

# 27. CRUD pattern with arrays

This is worth memorizing:

```text
Create
→ spread
```

```js

```

```text

→ map()
```

```js

```

```text

→ map()
```

```js
items.map(item =>
  item.id === id
    ? updatedItem
    : item

```

```text
Delete
→ filter()
```

```js
items.filter(item =>
  item.id !== id

```

This pattern appears everywhere in React.

# 28. Why not `forEach()` for rendering?

You may ask:

> Why use `map()` instead of `forEach()`?

Because `forEach()` returns:

```js
undefined
```

Example:

```js
const result = [1, 2, 3].forEach(number => {
  return number * 2;
});

console.log(result);
```

Result:

```js
undefined
```

But `map()` returns:

```js
[2, 4, 6]
```

React needs an array of React elements.

So:

```jsx
items.map(item => (
  <Item />
))
```

works naturally.

# 29. Arrow function syntax inside `map()`

You will see both of these:

```jsx
products.map(product => (
  <ProductCard
    key={product.id}
    product={product}
  />
))
```

and:

```jsx
products.map(product => {
  return (
    <ProductCard
      key={product.id}
      product={product}
    />
  );
})
```

They mean the same thing.

With parentheses:

```js
item => (
  value
)
```

implicit return.

With braces:

```js
item => {
  return value;
}
```

explicit return.

# 32. Multiple elements per mapped item

Suppose you need:

```jsx
<h2>{user.name}</h2>
<p>{user.email}</p>
```

You cannot return two sibling elements without a wrapper.

Use:

```jsx
{users.map(user => (
  <div key={user.id}>
    <h2>{user.name}</h2>
    <p>{user.email}</p>
  </div>
))}
```

Or use a Fragment.

But if you need a key on a Fragment, the shorthand:

```jsx
<>
</>
```

cannot accept a key.

Use:

```jsx
import { Fragment } from "react";

{users.map(user => (
  <Fragment key={user.id}>
    <h2>{user.name}</h2>
    <p>{user.email}</p>
  </Fragment>
))}
```

# 33. Data usually comes from an API

In a real app, your array may not be hardcoded.

Instead:

```text
API
 ↓
JSON array
 ↓
state
 ↓
map()
 ↓
components
```

Example:

```jsx
const [users, setUsers] = useState([]);

useEffect(() => {
  fetch("/api/users")
    .then(response => response.json())
    .then(data => setUsers(data));

```

Then:

```jsx
{users.map(user => (
  <UserCard
    key={user.id}
    user={user}
  />
))}
```

This is one of the most common React patterns in professional applications.

# 34. Full realistic example

```jsx
import { useState } from "react";

function ProductCard({ product, onDelete }) {
  return (
    <article>
      <h2>{product.name}</h2>

      <p>${product.price}</p>

      <p>
        {product.inStock
          ? "In Stock"
          : "Out of Stock"}
      </p>

      <button
        onClick={() => onDelete(product.id)}
      >
        Delete
      </button>
    </article>
  );
}

function App() {
  const [products, setProducts] = useState([
    {
      id: 1,
      name: "Laptop",
      price: 1200,
      inStock: true
    },
    {
      id: 2,
      name: "Phone",
      price: 800,
      inStock: false
    },
    {
      id: 3,
      name: "Tablet",
      price: 500,
      inStock: true
    }
  ]);

  function deleteProduct(id) {
    setProducts(
      products.filter(
        product => product.id !== id
      )
    );
  }

  if (products.length === 0) {
    return <p>No products available.</p>;
  }

  return (
    <main>
      <h1>Products</h1>

      {products.map(product => (
        <ProductCard
          key={product.id}
          product={product}
          onDelete={deleteProduct}
        />
      ))}
    </main>
  );
}

export default App;
```

There is a lot of React knowledge in this example.

# Common Interview Questions

### 1. How do you render an array in React?

A good answer:

> We normally use JavaScript's `map()` method to transform each array item into a React element or component.

Example:

```jsx
users.map(user => (
  <UserCard
    key={user.id}
    user={user}
  />
))
```

---

### 2. Why do we use `map()` instead of `forEach()`?

> `map()` returns a new array, which can contain React elements. `forEach()` returns `undefined`, so it is not normally used directly for rendering lists.

---

### 3. Why does React need keys?

> Keys provide stable identity for list items so React can correctly determine which items were added, removed, moved, or preserved during reconciliation.

---

### 4. What is the best value for a key?

> A stable and unique ID associated with the data item is usually the best key.

Example:

```jsx
key={user.id}
```

---

### 5. Why should we avoid `Math.random()` as a key?

> Because it generates a new key on every render, causing React to treat existing components as new components. This can cause unnecessary remounting and state loss.

---

### 6. Why can array index be a bad key?

> If items are inserted, removed, or reordered, indexes can point to different logical items. This can cause React to preserve state for the wrong item.

---

### 7. How do you render only certain array items?

Use:

```text
filter()
+
map()
```

Example:

```jsx
products
  .filter(product => product.inStock)
  .map(product => (
    <ProductCard
      key={product.id}
      product={product}
    />
  ))
```

---

### 8. How do you remove an item from React state?

Use `filter()`:

```js
setUsers(
  users.filter(user => user.id !== id)
);
```

---

### 9. How do you update one item in an array state?

Usually with `map()`:

```js
setUsers(
  users.map(user =>
    user.id === id
      ? { ...user, active: true }
      : user
  )
);
```

---

### 10. Should we mutate arrays stored in React state?

Generally, no.

Avoid:

```js
users.push(newUser);
```

Prefer:

```js
setUsers([
  ...users,
  newUser
]);
```

React state should generally be treated as immutable.
