Handling user input in React usually means:

> **Read what the user types or selects, store that value in state, and use that state to control the UI.**

The most common pattern is called a **controlled component**.

## 1. Basic text input

Start with this:

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  function handleChange(event) {
    setName(event.target.value);
  }

  return (
    <div>
      <input
        type="text"
        value={name}
        onChange={handleChange}
      />

      <p>Hello {name}</p>
    </div>
  );
}

export default App;
```

The flow is:

```text
User types
   ↓
onChange fires
   ↓
handleChange(event)
   ↓
event.target.value
   ↓
setName(...)
   ↓
state changes
   ↓
component re-renders
   ↓
input + UI show new value
```

That is the foundation of form handling in React.

---

# 2. Why do we use `value`?

Look at:

```jsx
<input
  value={name}
  onChange={handleChange}
/>
```

This means:

```text
React state
   ↓
controls
   ↓
input value
```

If:

```js
name = "John";
```

the input shows:

```text
John
```

That is why it is called a **controlled input**.

React state is the source of truth.

---

# 3. What does `event.target.value` mean?

Suppose the user types:

```text
Kawshar
```

Then:

```js
event.target
```

refers to the input element.

And:

```js
event.target.value
```

is:

```text
Kawshar
```

So this:

```jsx
setName(event.target.value);
```

means:

> Store the current input value in React state.

---

# 4. Inline version

You can also write:

```jsx
<input
  value={name}
  onChange={event => setName(event.target.value)}
/>
```

This is fine for simple inputs.

For larger forms, named functions are usually easier to maintain.

---

# 5. Controlled vs uncontrolled input

This is an important React concept.

## Controlled

```jsx
const [name, setName] = useState("");

<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

React controls the value.

## Uncontrolled

```jsx
<input />
```

The browser DOM keeps track of the current value.

You can also access uncontrolled inputs with refs.

For most beginner React forms, focus on controlled inputs first.

---

# 6. Handling multiple inputs

Suppose you have:

```text
Name
Email
Age
```

You could create separate state values:

```jsx
const [name, setName] = useState("");
const [email, setEmail] = useState("");
const [age, setAge] = useState("");
```

Then:

```jsx
<input
  value={name}
  onChange={e => setName(e.target.value)}
/>

<input
  value={email}
  onChange={e => setEmail(e.target.value)}
/>

<input
  value={age}
  onChange={e => setAge(e.target.value)}
/>
```

This is perfectly valid for small forms.

---

# 7. Using one object for a form

For larger forms, you can use one object.

```jsx
import { useState } from "react";

function App() {
  const [form, setForm] = useState({
    name: "",
    email: "",
    age: ""
  });

  return (
    <div>
      <input
        value={form.name}
        onChange={e =>
          setForm({
            ...form,
            name: e.target.value
          })
        }
      />

      <input
        value={form.email}
        onChange={e =>
          setForm({
            ...form,
            email: e.target.value
          })
        }
      />

      <input
        value={form.age}
        onChange={e =>
          setForm({
            ...form,
            age: e.target.value
          })
        }
      />
    </div>
  );
}
```

The important part is:

```js
{
  ...form,
  name: e.target.value
}
```

This preserves the other fields.

---

# 8. Why use `...form`?

Suppose:

```js
form = {
  name: "John",
  email: "john@example.com",
  age: "25"
};
```

If you do:

```jsx
setForm({
  name: "Sarah"
});
```

you replace the whole object.

Result:

```js
{
  name: "Sarah"
}
```

You lose:

```text
email
age
```

Instead:

```jsx
setForm({
  ...form,
  name: "Sarah"
});
```

produces:

```js
{
  name: "Sarah",
  email: "john@example.com",
  age: "25"
}
```

---

# 9. One reusable change handler

A better form pattern is:

```jsx
function handleChange(e) {
  const { name, value } = e.target;

  setForm({
    ...form,
    [name]: value
  });
}
```

Then your inputs:

```jsx
<input
  name="name"
  value={form.name}
  onChange={handleChange}
/>

<input
  name="email"
  value={form.email}
  onChange={handleChange}
/>

<input
  name="age"
  value={form.age}
  onChange={handleChange}
/>
```

This:

```js
[name]: value
```

is dynamic object property syntax.

If:

```text
name="email"
```

then React effectively does:

```js
{
  email: value
}
```

# 10. Textarea

In React, textarea is handled like a normal controlled input.

```jsx
const [message, setMessage] = useState("");

<textarea
  value={message}
  onChange={e => setMessage(e.target.value)}
/>
```

Do not normally write:

```html
<textarea>Hello</textarea>
```

for controlled React forms.

Use:

```jsx
value={message}
```

instead.

Example:

```jsx
const [country, setCountry] = useState("");

<select
  value={country}
  onChange={e => setCountry(e.target.value)}

  <option value="">
    Select Country
  </option>

  <option value="bd">
    Bangladesh
  </option>

  <option value="us">
    United States
  </option>

  <option value="uk">
    United Kingdom
  </option>
</select>
```

The selected option is controlled by:

```jsx
value={country}
```

# 12. Checkbox input

Checkboxes are different.

For text inputs, you use:

```js
e.target.value
```

For checkboxes, you usually use:

```js
e.target.checked
```

Example:

```jsx
const [accepted, setAccepted] = useState(false);

<input
  type="checkbox"
  checked={accepted}
  onChange={e => setAccepted(e.target.checked)}
/>
```

Flow:

```text
Unchecked
   ↓
User clicks
   ↓
e.target.checked = true
   ↓
setAccepted(true)
```

---

# 13. Important: `value` vs `checked`

For:

```text
text
email
password
number
textarea
select
```

usually use:

```jsx
value
```

For:

```text
checkbox
radio
```

usually use:

```jsx
checked
```

# 14. Radio buttons

Example:

```jsx
const [role, setRole] = useState("");

<label>
  <input
    type="radio"
    value="developer"
    checked={role === "developer"}
    onChange={e => setRole(e.target.value)}
  />
  Developer
</label>

<label>
  <input
    type="radio"
    value="designer"
    checked={role === "designer"}
    onChange={e => setRole(e.target.value)}
  />
  Designer
</label>
```

If the user selects Developer:

```text
role = "developer"
```

Then:

```jsx
checked={role === "developer"}
```

becomes true.

# 15. Number inputs

Suppose:

```jsx
const [age, setAge] = useState("");
```

Input:

```jsx
<input
  type="number"
  value={age}
  onChange={e => setAge(e.target.value)}
/>
```

Important:

`e.target.value` is usually a string.

So if the user types:

```text
25
```

you may still get:

```js
"25"
```

not:

```js
25
```

If you need a number:

```jsx
setAge(Number(e.target.value));
```

But be careful with empty input values.

For beginner forms, keeping form input state as strings is often simpler until submission.

# 16. Handling form submission

Example:

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  function handleSubmit(e) {
    e.preventDefault();

    console.log("Submitted:", name);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={name}
        onChange={e => setName(e.target.value)}
      />

      <button type="submit">
        Submit
      </button>
    </form>
  );
}
```

The important part:

```js
e.preventDefault();
```

Without it, a browser form normally performs its default submission behavior.

In a React SPA, you often want to handle the submission yourself.

---

# 17. Why use `onSubmit` instead of button `onClick`?

Prefer:

```jsx
<form onSubmit={handleSubmit}>
```

instead of relying only on:

```jsx
<button onClick={handleSubmit}>
```

Why?

A form can be submitted by:

```text
Clicking submit
Pressing Enter
Accessibility/browser behavior
```

So `onSubmit` is the correct semantic event.

---

# 18. A complete login form

```jsx
import { useState } from "react";

function LoginForm() {
  const [form, setForm] = useState({
    email: "",
    password: ""
  });

  function handleChange(e) {
    const { name, value } = e.target;

    setForm(prevForm => ({
      ...prevForm,
      [name]: value
    }));
  }

  function handleSubmit(e) {
    e.preventDefault();

    console.log(form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        name="email"
        value={form.email}
        onChange={handleChange}
        placeholder="Email"
      />

      <input
        type="password"
        name="password"
        value={form.password}
        onChange={handleChange}
        placeholder="Password"
      />

      <button type="submit">
        Login
      </button>
    </form>
  );
}
```

This is a very common React form pattern.

---

# 19. Why use `prevForm`?

Instead of:

```jsx
setForm({
  ...form,
  [name]: value
});
```

you can use:

```jsx
setForm(prevForm => ({
  ...prevForm,
  [name]: value
}));
```

This is preferable when the next state depends on the previous state.

It avoids relying on a possibly older render snapshot.

# 20. Basic validation

Suppose:

```jsx
const [email, setEmail] = useState("");
const [error, setError] = useState("");
```

Submit:

```jsx
function handleSubmit(e) {
  e.preventDefault();

  if (!email) {
    setError("Email is required");
    return;
  }

  setError("");

  console.log("Form submitted");
}
```

Render:

```jsx
{error && (
  <p>{error}</p>
)}
```

Flow:

```text
Submit
  ↓
Validate input
  ↓
Invalid?
  ↓
Show error

or

Valid?
  ↓
Continue submission
```

---

# 21. Live validation

You can also validate while typing.

Example:

```jsx
function handleChange(e) {
  const value = e.target.value;

  setEmail(value);

  if (!value.includes("@")) {
    setError("Enter a valid email");
  } else {
    setError("");
  }
}
```

But be careful.

Too much validation while the user is typing can create a poor experience.

Often a better strategy is validation:

```text
On blur
On submit
Or after user interaction
```

# 22. `onBlur`

`onBlur` runs when the input loses focus.

Example:

```jsx
const [error, setError] = useState("");

function handleBlur(e) {
  if (!e.target.value) {
    setError("This field is required");
  }
}

<input
  onBlur={handleBlur}
/>
```

Useful for form validation.

# 23. Handling multiple checkboxes

Suppose a user can select:

```text
React
JavaScript
Node.js
```

State:

```jsx
const [skills, setSkills] = useState([]);
```

Handler:

```jsx
function handleSkillChange(e) {
  const { value, checked } = e.target;

  if (checked) {
    setSkills(prevSkills => [
      ...prevSkills,
      value
    ]);
  } else {
    setSkills(prevSkills =>
      prevSkills.filter(skill => skill !== value)
    );
  }
}
```

Inputs:

```jsx
<input
  type="checkbox"
  value="React"
  checked={skills.includes("React")}
  onChange={handleSkillChange}
/>

<input
  type="checkbox"
  value="JavaScript"
  checked={skills.includes("JavaScript")}
  onChange={handleSkillChange}
/>
```

# 24. File input

File input behaves differently.

Example:

```jsx
function handleFileChange(e) {
  const file = e.target.files[0];

  console.log(file);
}
```

Input:

```jsx
<input
  type="file"
  onChange={handleFileChange}
/>
```

Notice:

```js
e.target.files
```

instead of:

```js
e.target.value
```

For file uploads, you usually work with `File` objects and often `FormData`.

After successful submission:

```jsx
setForm({
```

# 26. Dynamic form example

```jsx
import { useState } from "react";

function ContactForm() {
  const [form, setForm] = useState({
    name: "",
    email: "",
    message: "",
    subscribe: false
  });

  function handleChange(e) {
    const {
      name,
      value,
      type,
      checked
    } = e.target;

    setForm(prevForm => ({
      ...prevForm,
      [name]:
        type === "checkbox"
          ? checked
          : value
    }));
  }

  function handleSubmit(e) {
    e.preventDefault();

    console.log(form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        name="name"
        value={form.name}
        onChange={handleChange}
      />

      <input
        type="email"
        name="email"
        value={form.email}
        onChange={handleChange}
      />

      <textarea
        name="message"
        value={form.message}
        onChange={handleChange}
      />

      <label>
        <input
          type="checkbox"
          name="subscribe"
          checked={form.subscribe}
          onChange={handleChange}
        />

        Subscribe
      </label>

      <button type="submit">
        Send
      </button>
    </form>
  );
}
```

This single handler works with both text inputs and a checkbox.

---

# 27. Understand this important line

```jsx
[name]:
  type === "checkbox"
    ? checked
    : value
```

If the input is:

```jsx
<input name="email" />
```

then:

```text
name = "email"
value = whatever user typed
```

So it updates:

```js
form.email
```

If:

```jsx
<input
  type="checkbox"
  name="subscribe"
/>
```

then it uses:

```js
checked
```

instead.

# 28. Do not mutate form state

Bad:

```jsx
form.name = e.target.value;

setForm(form);
```

Better:

```jsx
setForm(prevForm => ({
  ...prevForm,
  name: e.target.value
}));
```

React state should be treated as immutable.

---

# 29. Controlled input warning

A common mistake is:

```jsx
const [name, setName] = useState();

<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

Initially:

```js
name === undefined
```

Later it becomes a string.

React may warn about switching between uncontrolled and controlled input behavior.

For text fields, initialize with:

```jsx
useState("")
```

not:

```jsx
useState()
```

Good:

```jsx
const [name, setName] = useState("");
```

# 30. Common initial values

For text:

```jsx
useState("")
```

For checkbox:

```jsx
useState(false)
```

For arrays:

```jsx
useState([])
```

For object form:

```jsx
useState({
  name: "",
  email: ""
})
```

These initial values help keep the form controlled from the beginning.

# 31. User input does not need state every time

This is an important advanced point.

Not every input must always be controlled.

Sometimes uncontrolled inputs with refs can be appropriate.

Example:

```jsx
const inputRef = useRef(null);

function handleSubmit() {
  console.log(inputRef.current.value);
}

<input ref={inputRef} />
```

But for learning React forms, controlled components are the best place to start.

# 32. Forms and API requests

A common real-world flow is:

```text
User types
   ↓
React state
   ↓
Submit
   ↓
Validate
   ↓
API request
   ↓
Success / error
```

Example:

```jsx
async function handleSubmit(e) {
  e.preventDefault();

  const response = await fetch("/api/contact", {
    method: "POST",
    headers: {
      "Content-Type": "application/json"
    },
    body: JSON.stringify(form)
  });

  if (response.ok) {
    console.log("Submitted");
  }
}
```

This is where event handlers, state, and user input all come together.

# 33. State structure matters

Avoid storing unnecessary duplicate data.

Bad:

```jsx
const [firstName, setFirstName] = useState("");
const [lastName, setLastName] = useState("");
const [fullName, setFullName] = useState("");
```

Better:

```jsx
const [firstName, setFirstName] = useState("");
const [lastName, setLastName] = useState("");

const fullName = `${firstName} ${lastName}`;
```

If a value can be calculated from existing state, you often do not need another state variable.

# 34. Common beginner mistakes

### Mistake 1

Input doesn't update:

```jsx
<input value={name} />
```

Why?

There is no `onChange`.

Correct:

```jsx
<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

---

### Mistake 2

Using `value` for checkbox state:

```jsx
<input
  type="checkbox"
  value={accepted}
/>
```

Better:

```jsx
<input
  type="checkbox"
  checked={accepted}
  onChange={e => setAccepted(e.target.checked)}
/>
```

---

### Mistake 3

Mutating object state:

```js
form.email = "test@example.com";
```

Use:

```jsx
setForm(prev => ({
  ...prev,
  email: "test@example.com"
}));
```

---

### Mistake 4

Forgetting:

```js
e.preventDefault();
```

inside a form submit handler when you want client-side submission handling.

---

### Mistake 5

Using separate duplicated handlers for a large form.

Sometimes this:

```text
handleName
handleEmail
handleAge
handlePhone
handleAddress
```

can be simplified with:

```jsx
handleChange
```

using `name` attributes.

# Common Interview Questions

### 1. How do you handle user input in React?

A strong answer:

> We commonly store input values in state and use event handlers such as `onChange` to update that state. This creates a controlled component where React state is the source of truth.

---

### 2. What is a controlled component?

> A controlled component is a form element whose value is controlled by React state.

Example:

```jsx
<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

---

### 3. What is an uncontrolled component?

> An uncontrolled component keeps its current value primarily in the DOM instead of React state, and it is commonly accessed using a ref.

---

### 4. What is `event.target.value`?

> It is the current value of the form element that triggered the event.

---

### 5. How do you handle checkboxes?

Use:

```jsx
e.target.checked
```

and:

```jsx
checked={state}
```

---

### 6. How do you handle multiple form fields with one handler?

Give each input a `name`:

```jsx
name="email"
```

Then:

```jsx
function handleChange(e) {
  const { name, value } = e.target;

  setForm(prev => ({
    ...prev,
    [name]: value
  }));
}
```

---

### 7. Why do we use `preventDefault()` on form submission?

> To prevent the browser's default form submission behavior so the React application can handle submission itself.

---

### 8. Why should form state not be mutated directly?

> React state should be treated as immutable. Creating new objects or arrays makes updates predictable and allows React to correctly process state changes.

---

### 9. Why use `onSubmit` instead of only button `onClick`?

> Because the form can be submitted in multiple ways, including pressing Enter, and `onSubmit` correctly represents the form submission event.

---

### 10. What is the difference between `value` and `checked`?

Use:

```text
value
```

for text-like inputs and selects.

Use:

```text
checked
```

for:

```text
checkbox
radio
```

---

# The mental model to remember

For a controlled input:

```text
React State
    ↓
value={state}
    ↓
Input
    ↓
User types
    ↓
onChange
    ↓
event.target.value
    ↓
setState()
    ↓
React re-renders
    ↓
Input shows new state
```

And memorize these four patterns:

```jsx
const [name, setName] = useState("");
```

```jsx
<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

```jsx
<input
  type="checkbox"
  checked={accepted}
  onChange={e => setAccepted(e.target.checked)}
/>
```

```jsx
<form onSubmit={handleSubmit}>
```

Once those patterns are clear, you already understand the foundation of user input handling in React.
