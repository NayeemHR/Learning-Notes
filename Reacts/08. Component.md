A **React Component** is a reusable piece of UI.

In modern React, a component is usually a **JavaScript function that returns JSX**.

The simplest example is:

```jsx
function Welcome() {
  return <h1>Hello React</h1>;
}
```

Then you use it like this:

```jsx
<Welcome />
```

The key idea is:

> A component combines UI structure and related logic into a reusable unit.

# 1. Why do we need components?

Imagine a website:

```text
Website
├── Header
├── Hero
├── Services
├── Testimonials
├── Contact Form
└── Footer
```

Without components, you could put everything inside one huge file.

That becomes difficult to:

```text
Understand
Reuse
Maintain
Test
Update
```

With React, you can create:

```jsx
<Header />
<Hero />
<Services />
<Testimonials />
<ContactForm />
<Footer />
```

Now each part has its own responsibility.

---

# 2. A component is a JavaScript function

Look at this:

```jsx
function Header() {
  return <header>My Website</header>;
}
```

This is just a JavaScript function.

But it returns React UI.

Compare it with a normal JavaScript function:

```js
function add(a, b) {
  return a + b;
}
```

React component:

```jsx
function Header() {
  return <h1>My Website</h1>;
}
```

The difference is mainly what it returns.

```text
Normal function
→ returns normal JavaScript data

React component
→ returns React elements / JSX
```

---

# 3. Component names must start with a capital letter

Correct:

```jsx
function Header() {
  return <h1>Header</h1>;
}
```

Use:

```jsx
<Header />
```

Wrong:

```jsx
function header() {
  return <h1>Header</h1>;
}
```

If you write:

```jsx
<header />
```

React treats it as an HTML element, not your custom component.

Remember:

```text
lowercase
→ built-in HTML element

Capitalized
→ React component
```

Examples:

```jsx
<div />
<button />
section />
```

versus:

```jsx
<Header />
<Button />
<ProductCard />
```

# 4. Components return JSX

Example:

```jsx
function UserCard() {
  return (
    <div>
      <h2>John Doe</h2>
      <p>Frontend Developer</p>
    </div>
  );
}
```

JSX lets us describe UI.

You can think:

```text
Component
   ↓
returns
   ↓
JSX
   ↓
React renders UI
```

# 5. A component normally returns one root structure

This is invalid:

```jsx
function App() {
  return (
    <h1>Hello</h1>
    <p>Welcome</p>
  );
}
```

Because there are two top-level elements.

You can wrap them:

```jsx
function App() {
  return (
    <div>
      <h1>Hello</h1>
      <p>Welcome</p>
    </div>
  );
}
```

Or use a Fragment:

```jsx
function App() {
  return (
    <>
      <h1>Hello</h1>
      <p>Welcome</p>
    </>
  );
}
```

The `<>...</>` syntax is called a **Fragment**.

---

# 6. Components can use JavaScript

A component is not just HTML-like markup.

You can use normal JavaScript:

```jsx
function Greeting() {
  const name = "Kawshar";

  return <h1>Hello {name}</h1>;
}
```

The `{}` means:

> Evaluate this JavaScript expression.

You can do:

```jsx
function Price() {
  const price = 100;
  const tax = 20;

  return <p>Total: {price + tax}</p>;
}
```

Output:

```text
Total: 120
```

---

# 7. Components can receive data using props

This is where components become reusable.

Suppose:

```jsx
function UserCard() {
  return (
    <div>
      <h2>John</h2>
      <p>Developer</p>
    </div>
  );
}
```

That component always shows John.

Not very reusable.

Instead:

```jsx
function UserCard(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.job}</p>
    </div>
  );
}
```

Now:

```jsx
<UserCard
  name="John"
  job="Developer"
/>

<UserCard
  name="Sarah"
  job="Designer"
/>
```

Same component.

Different data.

That is one of the biggest reasons React components are useful.

---

# 8. Props with destructuring

Instead of:

```jsx
function UserCard(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.job}</p>
    </div>
  );
}
```

You will often see:

```jsx
function UserCard({ name, job }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{job}</p>
    </div>
  );
}
```

This is just JavaScript destructuring.

Remember:

```text
props
=
input given to a component
```

# 9. Think of a component like a function with inputs

Normal JavaScript:

```js
function greet(name) {
  return "Hello " + name;
}
```

React:

```jsx
function Greeting({ name }) {
  return <h1>Hello {name}</h1>;
}
```

Use:

```jsx
<Greeting name="John" />
```

You can mentally translate:

```jsx
<Greeting name="John" />
```

to something conceptually similar to:

```js
Greeting({
  name: "John"
});
```

Not exactly how React internally runs everything, but this is a useful beginner mental model.

# 10. Components can contain other components

This is called **composition**.

Example:

```jsx
function Header() {
  return <header>Header</header>;
}

function Footer() {
  return <footer>Footer</footer>;
}

function App() {
  return (
    <>
      <Header />
      <main>Main content</main>
      <Footer />
    </>
  );
}
```

Architecture:

```text
App
├── Header
├── Main
└── Footer
```

This is called a **component tree**.

# 11. Parent and child components

Example:

```jsx
function App() {
  return <UserCard name="John" />;
}
```

```jsx
function UserCard({ name }) {
  return <h2>{name}</h2>;
}
```

Here:

```text
App
=
Parent component
```

```text
UserCard
=
Child component
```

Data flows:

```text
Parent
   ↓ props
Child
```

React primarily follows one-way data flow.

# 12. What is `children`?

Suppose you create:

```jsx
<Card>
  <h2>Hello</h2>
  <p>Welcome to React</p>
</Card>
```

How does `Card` receive the content?

Through the special `children` prop.

Example:

```jsx
function Card({ children }) {
  return (
    <div className="card">
      {children}
    </div>
  );
}
```

Now:

```jsx
<Card>
  <h2>Hello</h2>
  <p>Welcome</p>
</Card>
```

React passes:

```jsx
<h2>Hello</h2>
<p>Welcome</p>
```

as `children`.

This is extremely important for reusable layouts.

---

# 13. Components can have state

Props come from outside.

State is changing data associated with the component.

Example:

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>{count}</p>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </div>
  );
}
```

Here:

```text
Counter
   ↓
owns state
   ↓
count
```

When:

```jsx
setCount(count + 1);
```

runs, React schedules a re-render.

---

# 14. Props vs State inside components

This is fundamental.

```text
Props
=
data received by a component
```

```text
State
=
changing data managed by a component
```

Example:

```jsx
function Product({ name }) {
  const [quantity, setQuantity] = useState(1);
}
```

Here:

```text
name
=
prop
```

```text
quantity
=
state
```

---

# 15. Components re-render

Suppose:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  console.log("render");

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  );
}
```

When state changes:

```text
setCount()
   ↓
React schedules update
   ↓
Counter function runs again
   ↓
New JSX is produced
   ↓
React reconciles
   ↓
Necessary DOM changes are committed
```

This connects to what you learned about reconciliation.

---

# 16. Re-render does not mean rebuild the entire DOM

Important distinction.

If:

```text
Count: 1
```

becomes:

```text
Count: 2
```

React may call the component again during rendering.

But React does not necessarily recreate the whole DOM subtree.

Conceptually:

```text
Component re-renders
       ↓
New React elements
       ↓
Reconciliation
       ↓
Only necessary DOM update
```

So:

```text
React component render
≠
DOM reconstruction
```

---

# 17. Components should be pure during rendering

This is an important modern React concept.

A component should normally behave like a pure function:

```text
Same inputs
   ↓
Same UI output
```

For example:

```jsx
function Greeting({ name }) {
  return <h1>Hello {name}</h1>;
}
```

Given:

```text
name = "John"
```

it should consistently return:

```text
Hello John
```

Avoid uncontrolled side effects directly during rendering.

For example, this is problematic:

```jsx
function App() {
  document.title = "Dashboard";

  return <h1>Dashboard</h1>;
}
```

Effects belong in appropriate APIs such as:

```jsx
useEffect(...)
```

when synchronization with an external system is needed.

---

# 18. Why should components be pure?

Because React may render components more than once.

With modern React, rendering work may be:

```text
Started
Paused
Restarted
Discarded
Repeated
```

This connects directly to Fiber.

So rendering should not unexpectedly:

```text
Send API requests
Modify external variables
Manipulate the DOM
Trigger payments
Write to databases
```

every time the function executes.

# 19. Component responsibility

A good component should have a clear job.

Example:

```jsx
function ProductCard({ product }) {
  return (
    <article>
      <h2>{product.name}</h2>
      <p>${product.price}</p>
      <button>Add to Cart</button>
    </article>
  );
}
```

Responsibility:

> Display one product card.

That's clear.

A problematic component might do:

```text
Product card rendering
Authentication
Payment processing
API fetching
Navigation
Analytics
Global theme
Search
```

all inside one file.

That becomes difficult to maintain.

# 20. When should you create a component?

A good rule:

Create a component when something is:

```text
Reusable
Repeated
Logically independent
Complex enough to isolate
A meaningful UI section
```

For example:

```text
Header
Footer
Navbar
Button
Modal
ProductCard
SearchBar
UserProfile
```

Good candidates.

You don't need to turn every:

```html
<div>
```

into a component.

# 21. Bad component splitting

You do not need:

```text
Heading.jsx
Paragraph.jsx
WrapperDiv.jsx
TinyIconWrapper.jsx
SectionContainerThing.jsx
```

just because React allows components.

Over-componentization makes code harder to follow.

Think in meaningful responsibilities.

# 22. Reusable component example

Bad:

```jsx
function BlueButton() {
  return <button>Buy Now</button>;
}
```

Then:

```jsx
function RedButton() {
  return <button>Delete</button>;
}
```

Instead, create one configurable component:

```jsx
function Button({ children, type = "button" }) {
  return (
    <button type={type}>
      {children}
    </button>
  );
}
```

Use:

```jsx
<Button>Buy Now</Button>

<Button>Delete</Button>

<Button type="submit">
  Submit
</Button>
```

This is reusable component design.

# 26. Functional components vs class components

Older React code often contains class components:

```jsx
class Welcome extends React.Component {
  render() {
    return <h1>Hello</h1>;
  }
}
```

Modern React mostly uses function components:

```jsx
function Welcome() {
  return <h1>Hello</h1>;
}
```

For your learning:

> Focus on function components.

You should recognize class components because you may encounter old code, but don't start there.

# 27. Component composition

Composition is one of React's most important ideas.

Instead of building one giant component:

```jsx
function App() {
  return (
    <div>
      {/* hundreds of lines */}
    </div>
  );
}
```

You compose smaller pieces:

```jsx
function App() {
  return (
    <>
      <Header />
      <Hero />
      <Services />
      <Testimonials />
      <Footer />
    </>
  );
}
```

Think:

```text
Small components
      +
Small components
      +
Small components
      ↓
Large application
```

# 30. Passing functions as props

Props can also contain functions.

Example:

```jsx
function App() {
  function handleDelete() {
    console.log("Delete product");
  }

  return (
    <ProductCard onDelete={handleDelete} />
  );
}
```

Child:

```jsx
function ProductCard({ onDelete }) {
  return (
    <button onClick={onDelete}>
      Delete
    </button>
  );
}
```

Now data/function communication is:

```text
Parent
  ↓ passes callback
Child
  ↓
User clicks
  ↓
Parent function executes
```

This pattern is extremely common.

# 31. Parent-to-child and child-to-parent communication

Parent → Child:

```text
Props
```

Child → Parent:

```text
Callback function passed through props
```

Example:

```jsx
function Parent() {
  function receiveMessage(message) {
    console.log(message);
  }

  return (
    <Child onSend={receiveMessage} />
  );
}
```

Child:

```jsx
function Child({ onSend }) {
  return (
    <button
      onClick={() => onSend("Hello Parent")}
    >
      Send
    </button>
  );
}
```

Important interview concept.

# 32. Conditional UI inside components

Components can decide what to render.

Example:

```jsx
function UserStatus({ loggedIn }) {
  if (loggedIn) {
    return <h2>Welcome back</h2>;
  }

  return <h2>Please login</h2>;
}
```

Or:

```jsx
function UserStatus({ loggedIn }) {
  return (
    <h2>
      {loggedIn ? "Welcome back" : "Please login"}
    </h2>
  );
}
```

# 34. Component identity

React cares about whether a component is considered the same component between renders.

For example:

```jsx
<UserProfile user="John" />
```

Then:

```jsx
<UserProfile user="Sarah" />
```

Same component type:

```text
UserProfile
```

So React can preserve component state.

But:

```jsx
<UserProfile />
```

changes to:

```jsx
<AdminProfile />
```

Now React sees a different component type.

State may be reset.

This connects components directly with reconciliation.

# 35. Component lifecycle in modern React

You may hear interviewers ask:

> What is the lifecycle of a React component?

With function components, think conceptually:

```text
Mount
 ↓
Update
 ↓
Unmount
```

### Mount

Component appears for the first time.

### Update

Props/state change and component renders again.

### Unmount

Component is removed from the tree.

You use Hooks such as `useEffect` when you need to synchronize external behavior with these stages.


# 40. A complete example

```jsx
import { useState } from "react";

function ProductCard({ name, price }) {
  const [quantity, setQuantity] = useState(1);

  function increaseQuantity() {
    setQuantity(quantity + 1);
  }

  return (
    <article>
      <h2>{name}</h2>

      <p>Price: ${price}</p>

      <p>Quantity: {quantity}</p>

      <button onClick={increaseQuantity}>
        Add One
      </button>
    </article>
  );
}

function App() {
  return (
    <>
      <ProductCard
        name="Laptop"
        price={1200}
      />

      <ProductCard
        name="Phone"
        price={800}
      />
    </>
  );
}

export default App;
```

Let's identify everything.

```text
ProductCard
→ reusable component
```

```text
App
→ parent component
```

```text
name
price
→ props
```

```text
quantity
→ state
```

```text
setQuantity
→ state updater
```

```text
increaseQuantity
→ event handler
```

```text
<ProductCard />
→ component usage
```

```text
App → ProductCard
→ parent-to-child relationship
```

That one example combines several core React concepts.

# Common React Component Interview Questions

### 1. What is a React component?

A strong answer:

> A React component is a reusable unit of UI. Modern React components are usually JavaScript functions that accept inputs such as props and return React elements, typically written using JSX.

### 2. What is the difference between a component and an element?

> A component is a function or component definition, while a React element is the description of UI created when JSX such as `<Button />` is evaluated.

### 3. What are props?

> Props are read-only inputs passed from a parent component to a child component.

### 4. What is state?

> State is data associated with a component that can change over time and cause React to schedule a re-render.

### 5. Props vs state?

> Props come from outside the component, while state represents changing data managed by React for the component.

### 6. Why must component names start with capital letters?

> React treats lowercase JSX tags as built-in host elements such as HTML tags, while capitalized names are treated as custom React components.

### 7. What is component composition?

> Component composition is the practice of building larger interfaces by combining smaller components.

### 8. What is the `children` prop?

> `children` is a special prop containing the content placed between a component's opening and closing tags.

Example:

```jsx
<Card>
  <p>Hello</p>
</Card>
```

### 9. What causes a component to re-render?

Typical causes include:

```text
Its state changes
Its parent renders
Relevant context changes
```

New props often arrive because the parent rendered with different values.

### 10. Does re-render mean the DOM is recreated?

No.

> React can re-evaluate the component, reconcile the new result with the previous tree, and commit only the necessary DOM changes.

### 11. What is a pure component conceptually?

> A pure component produces predictable UI from its inputs and avoids side effects during rendering.

### 12. Functional vs class components?

> Function components are the standard modern React approach and use Hooks for state and other React features. Class components are an older API that still exists in legacy code.

# The mental model you should remember

Think of a React component like this:

```text
        Props
          ↓
    ┌───────────┐
    │ Component │
    │           │
    │  State    │
    │  Logic    │
    └───────────┘
          ↓
         JSX
          ↓
          UI
```

Then interaction:

```text
User clicks
    ↓
Event handler
    ↓
State changes
    ↓
Component re-renders
    ↓
Reconciliation
    ↓
Necessary DOM changes
```

For your current React learning stage, make sure you can confidently build and explain these four components without copying:

```jsx
<Greeting />
<Button />
<UserCard />
<Counter />
```

If you understand how **components + props + state + composition** work together, you have understood one of the most important foundations of React.
