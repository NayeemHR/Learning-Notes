React.js is a **JavaScript library for building user interfaces**, especially interfaces that are interactive, dynamic, and made from reusable pieces called **components**.

React was originally created at Facebook and is now maintained by Meta and the open-source community.

The simplest definition is:

> **React helps you build UI using reusable components and automatically update the UI when your data changes.**

## 1. What problem does React solve?

Suppose you build a dashboard with:

```text
Header
Sidebar
User Profile
Notifications
Orders Table
Search
Filters
Modal
Settings
```

With plain JavaScript, you often need to manually:

```js
document.querySelector(...)
element.innerHTML = ...
element.classList.add(...)
element.addEventListener(...)
```

That is fine for small projects.

But when your application becomes large and many pieces of data are changing, manually updating the DOM becomes difficult to manage.

React gives you a better structure.

Instead of manually changing the page, you describe:

```text
If the data looks like this,
the UI should look like this.
```

React handles the UI update.

---

# 2. React is component-based

A React application is usually divided into small reusable components.

For example:

```text
App
├── Header
├── Hero
├── ProductList
│   ├── ProductCard
│   ├── ProductCard
│   └── ProductCard
└── Footer
```

Each part can be a React component.

Example:

```jsx
function Header() {
  return <h1>My Website</h1>;
}
```

Another component:

```jsx
function ProductCard() {
  return (
    <div>
      <h2>MacBook Pro</h2>
      <p>$1999</p>
    </div>
  );
}
```

And then:

```jsx
function App() {
  return (
    <>
      <Header />
      <ProductCard />
    </>
  );
}
```

This makes applications easier to organize, reuse, test, and maintain.

---

# 3. What is a React component?

A React component is usually a JavaScript function that returns UI.

Example:

```jsx
function Welcome() {
  return <h1>Hello World</h1>;
}
```

Here:

```text
Welcome
```

is the component.

And:

```jsx
<h1>Hello World</h1>
```

is the UI it returns.

You can use it like this:

```jsx
<Welcome />
```

Think about components as custom HTML elements.

HTML gives you:

```html
<button></button>
<input />
<div></div>
```

React allows you to create:

```jsx
<ProductCard />
<UserProfile />
<Navbar />
<LoginForm />
```

---

# 4. What is JSX?

React commonly uses **JSX**.

JSX looks like HTML, but it is written inside JavaScript.

Example:

```jsx
const element = <h1>Hello React</h1>;
```

This is JSX.

You can also use JavaScript expressions inside JSX using `{}`.

Example:

```jsx
const name = "Kawshar";

function App() {
  return <h1>Hello {name}</h1>;
}
```

Output:

```text
Hello Kawshar
```

A useful rule:

```text
JSX = HTML-like syntax inside JavaScript
```

However, JSX is not actually HTML.

---

# 5. What are Props?

**Props** are used to pass data from one component to another.

Suppose you have:

```jsx
function UserCard(props) {
  return <h2>{props.name}</h2>;
}
```

You can use it like:

```jsx
<UserCard name="Alex" />
<UserCard name="John" />
<UserCard name="Sarah" />
```

The same component receives different data.

A more modern version uses destructuring:

```jsx
function UserCard({ name }) {
  return <h2>{name}</h2>;
}
```

Think about props like function arguments.

This:

```js
function greet(name) {
  return name;
}
```

is conceptually similar to:

```jsx
function UserCard({ name }) {
  return <h2>{name}</h2>;
}
```

---

# 6. What is State?

State is one of the most important React concepts.

**State is data inside a component that can change over time.**

For example:

```text
Counter value
Shopping cart
Logged-in status
Form input
Modal open/closed
Selected tab
Search term
```

Example:

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>{count}</p>

      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </div>
  );
}
```

Initially:

```text
count = 0
```

After clicking:

```text
count = 1
```

When the state changes, React re-renders the component.

That means:

```text
State changes
      ↓
Component re-renders
      ↓
UI updates
```

This is one of the core ideas behind React.

---

# 7. Props vs State

This is a very common interview question.

| Props                        | State                    |
| ---------------------------- | ------------------------ |
| Passed from parent           | Managed inside component |
| Usually read-only            | Can change               |
| Used to configure components | Used for changing data   |
| External data                | Internal component data  |

Example of props:

```jsx
<ProductCard name="Laptop" />
```

Example of state:

```jsx
const [quantity, setQuantity] = useState(1);
```

A simple way to remember:

```text
Props = data given to a component

State = data managed by a component
```

# 8. What is a Hook?

Hooks are special React functions that allow functional components to use React features.

Common hooks include:

```text
useState
useEffect
useContext
useRef
useMemo
useCallback
```

The first two you should learn are:

```text
useState
useEffect
```

# 9. What is useState?

`useState` lets a component remember changing data.

Example:

```jsx
const [name, setName] = useState("");
```

Here:

```text
name
```

is the current state.

```text
setName
```

updates the state.

```text
""
```

is the initial value.

Example:

```jsx
setName("John");
```

After that:

```text
name = "John"
```

React re-renders the component.

---

# 10. What is useEffect?

`useEffect` is used when your component needs to interact with something outside normal rendering.

Common examples:

```text
API requests
Timers
Event listeners
Document title
Subscriptions
Local storage
```

Example:

```jsx
import { useEffect } from "react";

function App() {
  useEffect(() => {
    console.log("Component loaded");
  }, []);

  return <h1>Hello</h1>;
}
```

The empty array:

```js
[]
```

means this effect runs after the initial render.

A common example is API fetching:

```jsx
useEffect(() => {
  fetch("https://api.example.com/users")
    .then(response => response.json())
    .then(data => console.log(data));
}, []);
```

---

# 11. What does rendering mean?

Rendering means React executes your component and determines what UI should appear.

Example:

```jsx
function App() {
  return <h1>Hello</h1>;
}
```

React renders:

```html
<h1>Hello</h1>
```

If state changes, React may render the component again.

This is called:

```text
re-rendering
```

---

# 12. What is the Virtual DOM?

This is probably one of the most common beginner React interview questions.

The browser has a real DOM.

For example:

```html
<body>
  <div>
    <h1>Hello</h1>
  </div>
</body>
```

React maintains an internal representation of the UI, commonly called the **Virtual DOM**.

Conceptually:

```text
State changes
      ↓
React creates new UI representation
      ↓
React compares it with previous one
      ↓
React determines what changed
      ↓
Necessary DOM updates are applied
```

React does not normally recreate your entire page every time something changes.

It works out the required updates.

---

# 13. What is reconciliation?

Reconciliation is the process React uses to compare the previous UI tree with the new UI tree and determine what needs to change.

For example:

Before:

```jsx
<h1>Count: 1</h1>
```

After:

```jsx
<h1>Count: 2</h1>
```

React determines that only the text needs to change.

This comparison and update process is called reconciliation.

For interviews, you can say:

> Reconciliation is React's process for determining how the UI should be updated after props or state change.

---

# 14. What is conditional rendering?

Conditional rendering means showing different UI depending on a condition.

Example:

```jsx
function Dashboard({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? <h1>Dashboard</h1> : <h1>Please Login</h1>}
    </div>
  );
}
```

If:

```js
isLoggedIn = true;
```

you see:

```text
Dashboard
```

Otherwise:

```text
Please Login
```

You can also use:

```jsx
{isAdmin && <AdminPanel />}
```

---

# 15. How do you render lists in React?

Usually with JavaScript's `map()`.

Example:

```jsx
const users = [
  { id: 1, name: "John" },
  { id: 2, name: "Sarah" },
  { id: 3, name: "David" }
];
```

Then:

```jsx
function App() {
  return (
    <div>
      {users.map(user => (
        <p key={user.id}>
          {user.name}
        </p>
      ))}
    </div>
  );
}
```

This is why learning `map()` before React is important.

---

# 16. What is a key in React?

When rendering lists, React needs a `key`.

Example:

```jsx
users.map(user => (
  <User key={user.id} name={user.name} />
))
```

The key helps React identify which item:

```text
was added
was removed
was updated
was reordered
```

Good:

```jsx
key={user.id}
```

Usually avoid:

```jsx
key={Math.random()}
```

And array index is not ideal when the list can change order.

---

# 17. What is event handling in React?

React handles events using JSX props such as:

```text
onClick
onChange
onSubmit
onMouseEnter
```

Example:

```jsx
function Button() {
  function handleClick() {
    console.log("Clicked");
  }

  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}
```

Notice:

```jsx
onClick={handleClick}
```

not:

```jsx
onClick={handleClick()}
```

The first passes the function.

The second immediately calls it.

---

# 18. What is one-way data flow?

React mainly follows **one-way data flow**.

Data normally moves:

```text
Parent
  ↓
Child
```

through props.

Example:

```jsx
function Parent() {
  const name = "John";

  return <Child name={name} />;
}
```

```jsx
function Child({ name }) {
  return <h1>{name}</h1>;
}
```

The parent sends data to the child.

This predictable direction makes applications easier to understand.

---

# 19. What does lifting state up mean?

Suppose two components need the same data.

Instead of storing separate state inside both components, you move the state to their nearest shared parent.

Example:

```text
          Parent
         state
        /     \
       ↓       ↓
   Child A   Child B
```

This is called **lifting state up**.

It allows both children to work with the same source of truth.

---

# 20. React is declarative

Another important interview concept.

Imperative JavaScript:

```js
const button = document.querySelector("#btn");

button.addEventListener("click", () => {
  document.querySelector("#message").textContent = "Welcome";
});
```

You explicitly tell the browser how to update the DOM.

React:

```jsx
function App() {
  const [loggedIn, setLoggedIn] = useState(false);

  return (
    <>
      <button onClick={() => setLoggedIn(true)}>
        Login
      </button>

      {loggedIn && <p>Welcome</p>}
    </>
  );
}
```

You describe what the UI should look like for the current state.

React takes care of the update.

That is declarative programming.

# Common React Interview Questions

Here are the questions I would expect you to know for a junior React interview.

### 1. What is React?

A strong answer:

> React is an open-source JavaScript library used to build component-based user interfaces. It allows developers to create reusable UI components and efficiently update the interface when state or props change.

---

### 2. Is React a framework or library?

React is primarily a **library**.

Its main responsibility is UI rendering.

For routing, data fetching, application structure, and other concerns, developers commonly use additional libraries or frameworks such as Next.js.

---

### 3. What is JSX?

> JSX is a syntax extension for JavaScript that allows us to write HTML-like markup inside JavaScript. React transforms JSX into JavaScript instructions that create UI elements.

Example:

```jsx
const element = <h1>Hello</h1>;
```

---

### 4. What is a component?

> A component is an independent and reusable piece of UI. Modern React components are usually JavaScript functions that return JSX.

Example:

```jsx
function Button() {
  return <button>Click</button>;
}
```

---

### 5. What are props?

> Props are values passed from a parent component to a child component. They are used to make components configurable and reusable.

---

### 6. What is state?

> State is data managed by a component that may change over time. When state changes, React schedules a re-render so the UI can reflect the new state.

---

### 7. Props vs state?

You can answer:

> Props are passed into a component by its parent, while state is managed by the component or by another state-management mechanism. Props are inputs; state represents changing application data.

---

### 8. What is useState?

> `useState` is a React Hook used to add state to functional components.

Example:

```jsx
const [count, setCount] = useState(0);
```

---

### 9. What is useEffect?

> `useEffect` is a React Hook used to synchronize a component with external systems, such as network requests, timers, browser APIs, or subscriptions.

That is a stronger modern answer than simply saying:

> "useEffect runs code after rendering."

---

### 10. What causes a React component to re-render?

Common causes include:

```text
State changes
Parent re-renders
Context values change
```

Receiving new props commonly happens because the parent rendered with different values.

---

### 11. What is the Virtual DOM?

> The Virtual DOM is a conceptual in-memory representation of the UI that React uses during rendering and reconciliation to determine what updates should be applied to the actual DOM.

---

### 12. What is reconciliation?

> Reconciliation is React's process of comparing UI trees between renders and determining how the DOM should be updated.

---

### 13. Why do we use keys?

> Keys help React uniquely identify elements in a list so it can correctly handle additions, removals, updates, and reordering.

---

### 14. What is conditional rendering?

> Conditional rendering means displaying different components or elements depending on application state or other conditions.

Example:

```jsx
{isLoggedIn ? <Dashboard /> : <Login />}
```

---

### 15. How do you render an array?

Usually with:

```js
map()
```

Example:

```jsx
users.map(user => (
  <User key={user.id} user={user} />
))
```

---

### 16. What is one-way data binding?

> React follows one-way data flow, meaning data typically flows from parent components down to child components through props.

---

### 17. What is lifting state up?

> Lifting state up means moving shared state to the closest common parent so multiple child components can access and update the same source of truth.

---

### 18. What is a Fragment?

Sometimes you need to return multiple elements without adding an unnecessary DOM element.

Instead of:

```jsx
<div>
  <Header />
  <Main />
</div>
```

you can use:

```jsx
<>
  <Header />
  <Main />
</>
```

This is a React Fragment.

Long version:

```jsx
<React.Fragment>
  <Header />
  <Main />
</React.Fragment>
```

---

### 19. What is the difference between controlled and uncontrolled components?

This is mainly asked regarding forms.

Controlled:

```jsx
const [name, setName] = useState("");

<input
  value={name}
  onChange={e => setName(e.target.value)}
/>
```

React state controls the value.

Uncontrolled:

```jsx
<input ref={inputRef} />
```

The DOM manages the current value, and you access it when necessary.

For most standard React forms, controlled components are very common.

---

### 20. What is the difference between React and React DOM?

React contains the core component and rendering model.

React DOM integrates React with the browser DOM.

For example:

```jsx
import { createRoot } from "react-dom/client";
```

Then:

```jsx
createRoot(document.getElementById("root")).render(
  <App />
);
```

# Interview Trap: Does React directly update the DOM every time state changes?

A weak answer would be:

> Yes, every state change updates the DOM.

Better answer:

> A state update causes React to schedule rendering. React calculates the new UI, reconciles it with the previous one, and commits the necessary changes to the DOM.

There is an important difference between:

```text
React rendering
```

and:

```text
Browser DOM update
```

They are not exactly the same operation.

---

# Interview Trap: Does useEffect always run once?

No.

This:

```jsx
useEffect(() => {
  // effect
});
```

can run after every relevant render.

This:

```jsx
useEffect(() => {
  // effect
}, []);
```

has no reactive dependencies, so it is generally used for synchronization tied to mounting/unmounting behavior.

This:

```jsx
useEffect(() => {
  // effect
}, [userId]);
```

runs when the relevant dependency `userId` changes.

There are additional development-mode details such as Strict Mode behavior, so saying simply "`[]` means exactly once forever" is not technically precise.

---

# Interview Trap: Can we modify state directly?

Avoid this:

```js
user.name = "John";
```

Or:

```js
items.push(newItem);
```

when those values are React state.

Instead, create a new value.

Example:

```js
setUser({
  ...user,
  name: "John"
});
```

For arrays:

```js
setItems([
  ...items,
  newItem
]);
```

React state should generally be treated as immutable.

# React Mental Model

Instead of trying to memorize everything, understand this flow:

```text
                Data
                 ↓
        ┌────────────────┐
        │   Component    │
        └────────────────┘
                 ↓
                JSX
                 ↓
                 UI
```

Then when state changes:

```text
User Action
    ↓
Event Handler
    ↓
State Update
    ↓
React Render
    ↓
Reconciliation
    ↓
Necessary UI changes
```

That flow explains a large percentage of beginner React.

# A Small Complete Example

```jsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  function increaseCount() {
    setCount(count + 1);
  }

  return (
    <div>
      <h1>Counter</h1>

      <p>Count: {count}</p>

      <button onClick={increaseCount}>
        Increase
      </button>
    </div>
  );
}

export default App;
```

You should be able to explain every part:

```text
useState
→ React Hook

count
→ current state

setCount
→ state updater function

useState(0)
→ initial state is 0

onClick
→ event

increaseCount
→ event handler

setCount(count + 1)
→ state update

{count}
→ JavaScript expression inside JSX

<App />
→ component
```

If you can explain this code clearly without memorizing sentences, you have understood the first major part of React.
