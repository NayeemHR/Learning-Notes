# 🚀 Real-World JavaScript Project: Shopping Cart

This is a great project for learning functions because almost every feature can be separated into a function.

Imagine you're building the JavaScript logic for an e-commerce website.

Our cart will support:

* Add product
* Remove product
* Calculate subtotal
* Calculate discount
* Calculate delivery charge
* Calculate final total
* Display cart

# 2. Why Do We Need Functions?

Imagine writing everything like this:

```js
// add product
// remove product
// calculate price
// calculate discount
// calculate delivery
// display cart
```

The code would quickly become difficult to maintain.

Instead, we separate responsibilities:

```text
addToCart()
removeFromCart()
calculateSubtotal()
calculateDiscount()
calculateDelivery()
calculateTotal()
displayCart()
```

### 🧠 Core principle

> **One function should ideally have one clear responsibility.**

This is called the **Single Responsibility Principle**.

# 5. Understanding `return` in Functions

This is an important concept.

Look at:

```js
function findProduct(productId) {
  const product = products.find(product => product.id === productId);

  return product;
}
```

Now:

```js
const product = findProduct(1);

console.log(product.name);
```

Output:

```text
Laptop
```

### 🧠 Mental model

A function can:

```text
Receive data
     ↓
Process data
     ↓
Return result
```

For example:

```js
function add(a, b) {
  return a + b;
}
```

Then:

```js
const result = add(10, 20);
```

The function gives a value back:

```text
30
```

This becomes extremely powerful when functions work together.

# 6. Create a `findProduct()` Function

Instead of putting product searching inside `addToCart()`, we can make a separate function.

```js
function findProduct(productId) {
  return products.find(product => product.id === productId);
}
```

Then:

```js
function addToCart(productId) {
  const product = findProduct(productId);

  if (!product) {
    console.log("Product not found");
    return;
  }

  cart.push(product);
}
```

Now our functions have clear responsibilities:

```text
findProduct()
     ↓
Find product

addToCart()
     ↓
Add product to cart
```

This is how real applications are structured.

# 7. Function #2 — Remove Product

Let's create:

```js
removeFromCart(productId)
```

We need to find the product's index.

```js
function removeFromCart(productId) {
  const index = cart.findIndex(product => product.id === productId);

  if (index === -1) {
    console.log("Product not found in cart");
    return;
  }

  cart.splice(index, 1);
}
```

Now:

```js
removeFromCart(2);
```

The mouse is removed.

### 🧠 New method

```js
findIndex()
```

returns the index of the first matching item.

If nothing is found:

```js
-1
```

# 8. Function #3 — Calculate Subtotal

Now we need:

```text
Laptop     80000
Mouse       1500
Keyboard    3000
----------------
Subtotal   84500
```

This is an accumulation problem.

```js
function calculateSubtotal() {
  return cart.reduce((total, product) => {
    return total + product.price;
  }, 0);
}
```

Then:

```js
const subtotal = calculateSubtotal();

console.log(subtotal);
```

Result:

```text
84500
```

### 🧠 Notice something important

Our function doesn't know **how** the cart was created.

It only knows:

> "Take the cart and calculate the total."

That's good function design.

---

# 9. Function #4 — Calculate Discount

Suppose:

```text
Subtotal >= 50000 → 10% discount
Otherwise         → 0%
```

Function:

```js
function calculateDiscount(subtotal) {
  if (subtotal >= 50000) {
    return subtotal * 0.10;
  }

  return 0;
}
```

Then:

```js
const subtotal = calculateSubtotal();
const discount = calculateDiscount(subtotal);

console.log(discount);
```

For `84500`:

```text
8450
```

---

# 10. Function #5 — Calculate Delivery

Let's say:

```text
Subtotal >= 50000 → Free delivery
Otherwise         → 100
```

Function:

```js
function calculateDelivery(subtotal) {
  if (subtotal >= 50000) {
    return 0;
  }

  return 100;
}
```

Now:

```js
const delivery = calculateDelivery(subtotal);
```

---

# 11. Function #6 — Calculate Final Total

Now we combine everything:

```js
function calculateTotal() {
  const subtotal = calculateSubtotal();
  const discount = calculateDiscount(subtotal);
  const delivery = calculateDelivery(subtotal);

  return subtotal - discount + delivery;
}
```

Then:

```js
console.log(calculateTotal());
```

For our example:

```text
Subtotal  = 84500
Discount  = 8450
Delivery  = 0
----------------
Total     = 76050
```

One function's output can become another function's input.

# 13. Let's Build `getCartSummary()`

Instead of calculating everything separately every time, we can return an object.

```js
function getCartSummary() {
  const subtotal = calculateSubtotal();
  const discount = calculateDiscount(subtotal);
  const delivery = calculateDelivery(subtotal);
  const total = subtotal - discount + delivery;

  return {
    subtotal,
    discount,
    delivery,
    total
  };
}
```

Now:

```js
const summary = getCartSummary();

console.log(summary);
```

Result:

```js
{
  subtotal: 84500,
  discount: 8450,
  delivery: 0,
  total: 76050
}
```

This is a **very useful real-world pattern**.

A function doesn't have to return only a number or string.

It can return:

```js
return {
  subtotal,
  discount,
  delivery,
  total
};
```

# 15. Complete Mini Project

Here's everything together:

```js
const products = [
  {
    id: 1,
    name: "Laptop",
    price: 80000
  },
  {
    id: 2,
    name: "Mouse",
    price: 1500
  },
  {
    id: 3,
    name: "Keyboard",
    price: 3000
  }
];

const cart = [];

function findProduct(productId) {
  return products.find(product => product.id === productId);
}

function addToCart(productId) {
  const product = findProduct(productId);

  if (!product) {
    console.log("Product not found");
    return;
  }

  cart.push(product);
}

function removeFromCart(productId) {
  const index = cart.findIndex(product => product.id === productId);

  if (index === -1) {
    console.log("Product not found in cart");
    return;
  }

  cart.splice(index, 1);
}

function calculateSubtotal() {
  return cart.reduce((total, product) => {
    return total + product.price;
  }, 0);
}

function calculateDiscount(subtotal) {
  if (subtotal >= 50000) {
    return subtotal * 0.10;
  }

  return 0;
}

function calculateDelivery(subtotal) {
  if (subtotal >= 50000) {
    return 0;
  }

  return 100;
}

function getCartSummary() {
  const subtotal = calculateSubtotal();
  const discount = calculateDiscount(subtotal);
  const delivery = calculateDelivery(subtotal);
  const total = subtotal - discount + delivery;

  return {
    subtotal,
    discount,
    delivery,
    total
  };
}
```

Then our application can do:

```js
addToCart(1);
addToCart(2);
addToCart(3);

console.log(getCartSummary());
```

# 16. A Real Developer's Thought Process

When you receive a project requirement:

> "Build a shopping cart with discounts and delivery."

Don't immediately start coding.

Break the requirement into tasks:

```text
Requirement
     ↓
What data do I need?
     ↓
What operations are required?
     ↓
Which functions represent those operations?
     ↓
What does each function receive?
     ↓
What does each function return?
```

For our project:

| Function              | Input       | Output        |
| --------------------- | ----------- | ------------- |
| `findProduct()`       | `productId` | product       |
| `addToCart()`         | `productId` | modifies cart |
| `removeFromCart()`    | `productId` | modifies cart |
| `calculateSubtotal()` | none        | number        |
| `calculateDiscount()` | subtotal    | number        |
| `calculateDelivery()` | subtotal    | number        |
| `getCartSummary()`    | none        | object        |

This is **real problem-solving**.
