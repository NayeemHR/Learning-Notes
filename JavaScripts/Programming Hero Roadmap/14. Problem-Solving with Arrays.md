# 🧠 Problem-Solving with Arrays in JavaScript

## 1. First: Don't Think About Methods

When you see a problem like:

> Find all numbers greater than 10.

Don't immediately think:

> "Should I use `filter()`?"

First think:

> **What exactly is the problem asking me to do?**

Given:

```js
const numbers = [5, 12, 8, 20, 3, 15];
```

We need:

```text
12
20
15
```

Now we can decide which tool fits.

# 2. The 5-Step Problem-Solving Process

Whenever you get an array problem, use this process:

```text
1. Understand the input
        ↓
2. Understand the expected output
        ↓
3. Think about the logic
        ↓
4. Choose the appropriate array method/loop
        ↓
5. Test with examples and edge cases
```

Let's practice this systematically.

# 3. Problem #1 — Find the Largest Number

Given:

```js
const numbers = [10, 25, 8, 42, 17];
```

Expected:

```text
42
```

### Step 1 — Understand the problem

We need to compare the numbers and keep track of the largest one.

### Step 2 — Create a mental model

Start with:

```js
let largest = numbers[0];
```

Then:

```text
10 → largest = 10
25 → largest = 25
8  → keep 25
42 → largest = 42
17 → keep 42
```

### Step 3 — Write the algorithm

```js
let largest = numbers[0];

for (const number of numbers) {
  if (number > largest) {
    largest = number;
  }
}

console.log(largest);
```

Output:

```text
42
```

### 🧠 Important lesson

The important part isn't memorizing this code.

It's understanding this pattern:

> **Keep a variable that represents the best answer found so far.**

This pattern appears everywhere.

# 4. Problem #2 — Find the Smallest Number

Same idea.

```js
const numbers = [10, 25, 8, 42, 17];
```

We want:

```text
8
```

Solution:

```js
let smallest = numbers[0];

for (const number of numbers) {
  if (number < smallest) {
    smallest = number;
  }
}

console.log(smallest);
```

Notice the only major difference:

```js
number > largest
```

became:

```js
number < smallest
```

# 5. Problem #3 — Calculate the Sum

Given:

```js
const numbers = [10, 20, 30, 40];
```

Expected:

```text
100
```

Think:

```text
total = 0

10 → total = 10
20 → total = 30
30 → total = 60
40 → total = 100
```

Code:

```js
let total = 0;

for (const number of numbers) {
  total += number;
}

console.log(total);
```

This is called an **accumulator pattern**.

### 🧠 Pattern

```js
let result = initialValue;

for (const item of array) {
  result = result + something;
}
```

This pattern is extremely important.

# 6. Problem #4 — Count Something

Given:

```js
const numbers = [10, 15, 20, 25, 30];
```

How many numbers are greater than `20`?

Expected:

```text
2
```

Think:

```text
count = 0

10 → no
15 → no
20 → no
25 → yes → count = 1
30 → yes → count = 2
```

Code:

```js
let count = 0;

for (const number of numbers) {
  if (number > 20) {
    count++;
  }
}

console.log(count);
```

### 🧠 New pattern

> **Counting pattern**

```js
let count = 0;

for (const item of array) {
  if (condition) {
    count++;
  }
}
```

You'll use this constantly.

# 7. Problem #5 — Find Even Numbers

Given:

```js
const numbers = [1, 2, 3, 4, 5, 6];
```

Expected:

```js
[2, 4, 6]
```

Think:

> I need a **new array** containing only matching values.

So we can use `filter()`.

```js
const evenNumbers = numbers.filter(number => number % 2 === 0);

console.log(evenNumbers);
```

Result:

```js
[2, 4, 6]
```

But it's important to understand the loop version first:

```js
const evenNumbers = [];

for (const number of numbers) {
  if (number % 2 === 0) {
    evenNumbers.push(number);
  }
}
```

Then:

```js
console.log(evenNumbers);
```

### 🧠 Problem-solving connection

```text
Need matching items?
        ↓
      filter()
```

# 8. Problem #6 — Transform Every Item

Given:

```js
const numbers = [1, 2, 3, 4];
```

Expected:

```js
[2, 4, 6, 8]
```

We're changing every item.

That's a **mapping/transformation** problem.

```js
const doubled = numbers.map(number => number * 2);
```

Result:

```js
[2, 4, 6, 8]
```

Loop version:

```js
const doubled = [];

for (const number of numbers) {
  doubled.push(number * 2);
}
```

### 🧠 Recognize this pattern

```text
Every item changes
        ↓
      map()
```

# 9. Problem #7 — Find One Item

Given:

```js
const numbers = [5, 10, 15, 20, 25];
```

Find the first number greater than `12`.

Expected:

```text
15
```

Use:

```js
const result = numbers.find(number => number > 12);

console.log(result);
```

Result:

```text
15
```

### Why `find()`?

Because we need **one item**, not an array of items.

Compare:

```js
numbers.find(number => number > 12);
```

→ `15`

versus:

```js
numbers.filter(number => number > 12);
```

→ `[15, 20, 25]`

### 🧠 Remember

```text
One matching item → find()

All matching items → filter()
```

# 10. Problem #8 — Check if Something Exists

Given:

```js
const numbers = [10, 20, 30, 40];
```

Does `30` exist?

You can use:

```js
numbers.includes(30);
```

Result:

```js
true
```

For a condition:

```js
const hasLargeNumber = numbers.some(number => number > 35);
```

Result:

```js
true
```

### Difference

```js
numbers.includes(30);
```

Checks for a specific value.

```js
numbers.some(number => number > 35);
```

Checks whether **at least one item satisfies a condition**.

# 11. Problem #9 — Remove Duplicates

This is a very common interview problem.

Given:

```js
const numbers = [1, 2, 2, 3, 4, 4, 5];
```

Expected:

```js
[1, 2, 3, 4, 5]
```

One modern solution:

```js
const uniqueNumbers = [...new Set(numbers)];

console.log(uniqueNumbers);
```

Output:

```js
[1, 2, 3, 4, 5]
```

### Why?

A `Set` stores unique values.

```js
new Set([1, 2, 2, 3, 3]);
```

becomes conceptually:

```text
1
2
3
```

Then:

```js
[...new Set(numbers)]
```

converts it back into an array.

# 12. Problem #10 — Reverse an Array

Given:

```js
const numbers = [1, 2, 3, 4, 5];
```

Expected:

```js
[5, 4, 3, 2, 1]
```

You could use:

```js
numbers.reverse();
```

But be careful:

> `reverse()` **mutates the original array**.

A safer approach when you want to preserve the original:

```js
const reversed = [...numbers].reverse();
```

Now:

```js
console.log(numbers);
```

still gives:

```js
[1, 2, 3, 4, 5]
```

while:

```js
console.log(reversed);
```

gives:

```js
[5, 4, 3, 2, 1]
```

# 13. Problem #11 — Array of Objects

Now let's move to the type of data you'll frequently encounter in real projects.

```js
const users = [
  { name: "Nayeem", age: 25 },
  { name: "Rahim", age: 17 },
  { name: "Karim", age: 30 }
];
```

### Find users who are adults

```js
const adults = users.filter(user => user.age >= 18);
```

Result:

```js
[
  { name: "Nayeem", age: 25 },
  { name: "Karim", age: 30 }
]
```

### Get only their names

```js
const names = adults.map(user => user.name);
```

Result:

```js
["Nayeem", "Karim"]
```

We can combine them:

```js
const adultNames = users
  .filter(user => user.age >= 18)
  .map(user => user.name);
```

Result:

```js
["Nayeem", "Karim"]
```

### 🧠 This is called method chaining.

```text
users
  ↓
filter()
  ↓
matching users
  ↓
map()
  ↓
names
```

# 14. Problem #12 — Sum Object Values

Given:

```js
const products = [
  { name: "Laptop", price: 80000 },
  { name: "Mouse", price: 1500 },
  { name: "Keyboard", price: 3000 }
];
```

We want:

```text
84500
```

This is an **accumulation** problem.

Modern JavaScript:

```js
const total = products.reduce((sum, product) => {
  return sum + product.price;
}, 0);

console.log(total);
```

Result:

```text
84500
```

### Understand `reduce()` before memorizing it

Think:

```text
sum = 0

Laptop    → 0 + 80000  = 80000
Mouse     → 80000 + 1500 = 81500
Keyboard  → 81500 + 3000 = 84500
```

So:

```js
reduce()
```

is especially useful when:

> **Many array values need to become one final value.**

Examples:

```text
array → sum
array → total
array → average
array → object
array → string
```

# 15. Your Array Problem-Solving Map

This is the cheat sheet I want you to remember:

| Problem                       | Tool         |
| ----------------------------- | ------------ |
| Loop through items            | `for...of`   |
| Do something for every item   | `forEach()`  |
| Transform every item          | `map()`      |
| Get matching items            | `filter()`   |
| Get first matching item       | `find()`     |
| Check if at least one matches | `some()`     |
| Check if all match            | `every()`    |
| Find total/single result      | `reduce()`   |
| Check exact value             | `includes()` |
| Remove duplicates             | `Set`        |
| Sort                          | `sort()`     |
| Reverse                       | `reverse()`  |

But don't memorize the table blindly.

Ask yourself:

> **What shape should my answer have?**

For example:

```text
"I need all matching users"
        ↓
      Array
        ↓
     filter()

"I need the first matching user"
        ↓
      Object
        ↓
      find()

"I need the names of every user"
        ↓
      Array
        ↓
      map()

"I need the total price"
        ↓
      Number
        ↓
     reduce()
```

That's the real skill.
