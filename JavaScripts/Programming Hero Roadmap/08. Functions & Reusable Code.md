Absolutely. You've now learned **variables → data types → operators → strings → conditions → truthy/falsy**. The next big step is **Functions**.

Functions are one of the most important concepts in JavaScript because they allow you to write code once and **reuse it whenever you need it**.

# 🧠 Lesson 7: Functions & Reusable Code in JavaScript

## 1. What is a Function?

A **function is a reusable block of code designed to perform a specific task.**

For example, imagine you need to print a welcome message 10 times.

Without a function:

```js
console.log("Welcome Nayeem");
console.log("Welcome Nayeem");
console.log("Welcome Nayeem");
```

That's repetitive.

With a function:

```js
function welcome() {
    console.log("Welcome Nayeem");
}
```

Now you can reuse it:

```js
welcome();
welcome();
welcome();
```

### 🧠 Think of a function as a machine

```text
Input
  ↓
[ FUNCTION ]
  ↓
Output
```

For example:

```text
20 + 30
   ↓
[ add() ]
   ↓
50
```

---

# 2. Function Declaration

The basic syntax is:

```js
function functionName() {
    // code
}
```

Example:

```js
function sayHello() {
    console.log("Hello!");
}
```

But notice something important:

**The function doesn't run when you create it.**

You have to **call** it:

```js
sayHello();
```

Output:

```text
Hello!
```

---

# 3. Function Call

This:

```js
sayHello();
```

is called a **function call** or **function invocation**.

Think:

```js
function sayHello() {
    console.log("Hello");
}
```

= Create the function

```js
sayHello();
```

= Run the function

---

# 4. Why Do We Need Functions?

Imagine you have this:

```js
let price1 = 100;
let price2 = 200;
let price3 = 300;
```

You want to calculate VAT for each price.

Without a function:

```js
let vat1 = price1 * 0.15;
let vat2 = price2 * 0.15;
let vat3 = price3 * 0.15;
```

With a function:

```js
function calculateVat(price) {
    return price * 0.15;
}
```

Now:

```js
calculateVat(100);
calculateVat(200);
calculateVat(300);
```

Much better.

This is the basic idea behind **reusable code**.

---

# 5. Parameters

A function can receive data.

```js
function greet(name) {
    console.log("Hello " + name);
}
```

Here:

```js
name
```

is called a **parameter**.

Now we can call:

```js
greet("Nayeem");
```

Output:

```text
Hello Nayeem
```

And:

```js
greet("Rahim");
```

Output:

```text
Hello Rahim
```

The function is reusable because the input can change.

---

# 6. Parameter vs Argument

This is a common interview question.

Consider:

```js
function greet(name) {
    console.log("Hello " + name);
}

greet("Nayeem");
```

Here:

```js
name
```

is the **parameter**.

And:

```js
"Nayeem"
```

is the **argument**.

### Easy way to remember

> **Parameter → placeholder inside the function**

> **Argument → actual value you pass to the function**

---

# 7. Multiple Parameters

A function can accept multiple parameters.

```js
function add(a, b) {
    console.log(a + b);
}
```

Call it:

```js
add(10, 20);
```

Output:

```text
30
```

Another call:

```js
add(100, 50);
```

Output:

```text
150
```

That's reusable code.

---

# 8. `return`

This is one of the **most important things to understand about functions**.

Consider:

```js
function add(a, b) {
    return a + b;
}
```

When we call:

```js
add(10, 20);
```

the function returns:

```text
30
```

We can store that result:

```js
let result = add(10, 20);

console.log(result);
```

Output:

```text
30
```

### `return` gives a value back to the caller.

Think:

```text
10 + 20
   ↓
 add()
   ↓
 return 30
   ↓
 result = 30
```

---

# 9. `console.log()` vs `return`

This is **extremely important**.

### `console.log()`

Displays something in the console:

```js
function add(a, b) {
    console.log(a + b);
}
```

### `return`

Sends the value back:

```js
function add(a, b) {
    return a + b;
}
```

For reusable functions, `return` is usually more useful.

Example:

```js
function add(a, b) {
    return a + b;
}

let result = add(10, 20);

console.log(result * 2);
```

Output:

```text
60
```

If you only used `console.log()` inside `add()`, you wouldn't get the returned value to multiply.

---

# 1️⃣0️⃣ Function Stops at `return`

Once JavaScript reaches `return`, the function exits.

```js
function test() {
    return "Hello";

    console.log("World");
}
```

Calling:

```js
test();
```

returns:

```text
Hello
```

`"World"` is never printed.

Because:

```js
return
```

ends the function execution.

---

# 1️⃣1️⃣ Functions Can Return Different Data Types

A function doesn't have to return a number.

### String

```js
function getName() {
    return "Nayeem";
}
```

### Boolean

```js
function isAdult(age) {
    return age >= 18;
}
```

### Array

```js
function getSkills() {
    return ["HTML", "CSS", "JavaScript"];
}
```

### Object

```js
function getUser() {
    return {
        name: "Nayeem",
        age: 25
    };
}
```

# 1️⃣2️⃣ Function With Conditions

Functions and conditions work together constantly.

```js
function checkAge(age) {
    if (age >= 18) {
        return "Adult";
    } else {
        return "Minor";
    }
}
```

Now:

```js
console.log(checkAge(25));
```

Output:

```text
Adult
```

And:

```js
console.log(checkAge(15));
```

Output:

```text
Minor
```

# 1️⃣3️⃣ Default Parameters

You can give a parameter a default value.

```js
function greet(name = "Guest") {
    return `Hello ${name}`;
}
```

If we provide a name:

```js
console.log(greet("Nayeem"));
```

Output:

```text
Hello Nayeem
```

If we don't:

```js
console.log(greet());
```

Output:

```text
Hello Guest
```

Very useful when an argument may be missing.

# 1️⃣4️⃣ Function Expressions

You can store a function inside a variable.

```js
const greet = function () {
    console.log("Hello");
};
```

Then:

```js
greet();
```

This is called a **function expression**.

Compare:

### Function declaration

```js
function greet() {
    console.log("Hello");
}
```

### Function expression

```js
const greet = function () {
    console.log("Hello");
};
```

Both create functions, but their behavior differs in areas such as hoisting.

We'll study that later.

# ⭐ 1️⃣5️⃣ Arrow Functions

Modern JavaScript commonly uses **arrow functions**.

Instead of:

```js
const add = function (a, b) {
    return a + b;
};
```

You can write:

```js
const add = (a, b) => {
    return a + b;
};
```

And because this function contains only a return expression, you can shorten it:

```js
const add = (a, b) => a + b;
```

This is called an **arrow function**.

You'll see arrow functions everywhere in modern JavaScript, especially in React.

---

# 1️⃣6️⃣ Different Arrow Function Syntax

### No parameter

```js
const sayHello = () => {
    console.log("Hello");
};
```

### One parameter

```js
const greet = name => {
    console.log(`Hello ${name}`);
};
```

Parentheses are optional for a single parameter.

You can also write:

```js
const greet = (name) => {
    console.log(`Hello ${name}`);
};
```

Both are valid.

### Multiple parameters

```js
const add = (a, b) => {
    return a + b;
};
```

Parentheses are required.

# 1️⃣7️⃣ Reusable Function Example

Imagine you're building an e-commerce website.

You need to calculate the final price after discount.

Instead of repeating:

```js
let finalPrice1 = 1000 - (1000 * 0.10);
let finalPrice2 = 2000 - (2000 * 0.10);
let finalPrice3 = 5000 - (5000 * 0.10);
```

Create a reusable function:

```js
function calculateDiscount(price, discount) {
    return price - (price * discount / 100);
}
```

Now:

```js
console.log(calculateDiscount(1000, 10));
console.log(calculateDiscount(2000, 20));
console.log(calculateDiscount(5000, 15));
```

The same logic is reused with different inputs.

# 🧠 1️⃣8️⃣ Function Responsibility

A good function should ideally do **one clear job**.

Bad:

```js
function processUser() {
    // validate user
    // calculate price
    // send email
    // update database
    // change UI
}
```

That's doing too many things.

Better:

```js
function validateUser() {}

function calculatePrice() {}

function sendEmail() {}

function updateDatabase() {}
```

This is called **separation of concerns**.

You don't need to master the term yet, but start developing this habit:

> **One function → one clear responsibility.**

---

# ⭐ 1️⃣9️⃣ Functions Can Call Other Functions

Functions can work together.

```js
function add(a, b) {
    return a + b;
}

function double(number) {
    return number * 2;
}

let result = add(10, 20);

console.log(double(result));
```

First:

```text
10 + 20 = 30
```

Then:

```text
30 × 2 = 60
```

Output:

```text
60
```

This is how larger applications are built: **small reusable pieces working together.**

# 🔥 2️⃣0️⃣ A Function Is Also a Value

This is one of the concepts that makes JavaScript powerful.

You can store a function:

```js
const greet = () => {
    console.log("Hello");
};
```

in a variable.

You can also pass a function to another function:

```js
function execute(callback) {
    callback();
}

execute(greet);
```

Output:

```text
Hello
```

This idea leads to:

* Callback functions
* Higher-order functions
* Array methods like `map()`, `filter()`, `forEach()`
* Event handlers
* Promises
* React callbacks

We'll learn those later.
