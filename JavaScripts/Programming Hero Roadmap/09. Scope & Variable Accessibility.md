Absolutely. This is a **very important JavaScript topic**, especially for interviews. If you understand **scope**, you'll have a much easier time understanding closures, callbacks, modules, and React later.

# 🧠 Lesson 8: Scope & Variable Accessibility in JavaScript

First, let's understand the basic idea:

> **Scope determines where a variable can be accessed in your code.**

Think of scope like **rooms in a house**.

If a variable is created inside one room, people outside that room may not be able to access it.

```text
🏠 House
│
├── Room A
│    └── variable A
│
└── Room B
     └── variable B
```

A variable in Room A isn't automatically available in Room B.

---

# 1️⃣ What is Scope?

Consider:

```js
let name = "Nayeem";

console.log(name);
```

`name` is accessible because it was declared in the current/global scope.

But:

```js
if (true) {
    let age = 25;
}

console.log(age);
```

This gives an error.

Why?

Because `age` was created **inside the block**.

Its scope doesn't extend outside that block.

---

# 2️⃣ Types of Scope

In JavaScript, you'll mainly deal with:

1. **Global Scope**
2. **Function Scope**
3. **Block Scope**

And later you'll learn:

4. **Module Scope**
5. **Lexical Scope**

Let's start with the first three.

---

# 3️⃣ Global Scope

A variable declared outside functions and blocks is generally in the **global scope**.

```js
let name = "Nayeem";

function greet() {
    console.log(name);
}

greet();
```

Output:

```text
Nayeem
```

Why?

Because `name` is available from the global scope.

Think:

```text
Global Scope
│
├── name
│
└── greet()
      ↓
   can access name
```

---

# 4️⃣ Global Variables Can Be Accessed Inside Functions

Example:

```js
let country = "Bangladesh";

function showCountry() {
    console.log(country);
}

showCountry();
```

Output:

```text
Bangladesh
```

The function can access the variable because JavaScript looks outward when resolving variables.

---

# 5️⃣ But Local Variables Can't Be Accessed Outside

Consider:

```js
function greet() {
    let message = "Hello";
    
    console.log(message);
}

greet();
```

This works.

But:

```js
console.log(message);
```

outside the function gives an error.

Why?

Because:

```text
message
```

exists only inside the function.

This is called **function/local scope**.

---

# 6️⃣ Function Scope

Variables declared inside a function using `var`, `let`, or `const` are local to that function.

```js
function test() {
    let x = 10;
    const y = 20;
    var z = 30;
}

console.log(x); // Error
console.log(y); // Error
console.log(z); // Error
```

All three are inaccessible outside the function.

---

# ⭐ 7️⃣ Block Scope

This is especially important for `let` and `const`.

A **block** is code surrounded by `{}`.

For example:

```js
if (true) {
    let age = 25;
    const name = "Nayeem";
}
```

The `{}` creates a block.

So:

```js
console.log(age);
```

doesn't work outside it.

### Example

```js
if (true) {
    let message = "Hello";

    console.log(message); // ✅
}

console.log(message); // ❌
```

`message` only exists inside the block.

---

# 8️⃣ `let` and `const` Are Block-Scoped

Consider:

```js
if (true) {
    let x = 10;
    const y = 20;

    console.log(x);
    console.log(y);
}
```

Inside the block, both are accessible.

Outside:

```js
console.log(x); // ❌
console.log(y); // ❌
```

They are block-scoped.

---

# 🔥 9️⃣ `var` Is Function-Scoped

This is one of the **most important differences between `var` and `let`**.

Consider:

```js
if (true) {
    var x = 10;
}

console.log(x);
```

Output:

```text
10
```

Why?

Because `var` does **not** respect block scope.

It's function-scoped.

Compare:

```js
if (true) {
    let x = 10;
}

console.log(x); // ❌ Error
```

So:

```text
let    → block scoped
const  → block scoped
var    → function scoped
```

### Mentor rule ⭐

In modern JavaScript:

> **Prefer `const` and `let`. Avoid `var` unless you specifically need its behavior.**

---

# 1️⃣0️⃣ Nested Scope

Scopes can exist inside other scopes.

Example:

```js
let globalName = "Nayeem";

function outer() {
    let outerName = "Rahim";

    if (true) {
        let innerName = "Karim";

        console.log(globalName);
        console.log(outerName);
        console.log(innerName);
    }
}
```

Inside the deepest block, JavaScript can access:

```text
globalName
outerName
innerName
```

Think of it like nested boxes:

```text
🌍 Global Scope
│
│  globalName
│
└── Function Scope
    │
    │  outerName
    │
    └── Block Scope
        │
        │  innerName
        │
        └── Can access all three
```

---

# 1️⃣1️⃣ Scope Chain

This leads to an important concept:

> **Scope Chain**

When JavaScript sees a variable, it looks for it in the current scope first.

If it can't find it, it looks in the outer scope.

Then the next outer scope.

And so on.

Example:

```js
let a = 10;

function outer() {
    let b = 20;

    function inner() {
        let c = 30;

        console.log(c);
        console.log(b);
        console.log(a);
    }

    inner();
}

outer();
```

When `inner()` looks for `a`:

```text
inner scope
    ↓
outer scope
    ↓
global scope
    ↓
found a
```

That's the **scope chain**.

---

# 1️⃣2️⃣ Inner Scope Can Access Outer Scope

Example:

```js
let x = 10;

if (true) {
    let y = 20;

    console.log(x);
    console.log(y);
}
```

The inner block can access `x`.

But the reverse isn't true.

```js
if (true) {
    let y = 20;
}

console.log(y); // ❌
```

### Remember:

> **Inner → can access outer**

> **Outer → cannot access inner**

---

# 1️⃣3️⃣ Variable Shadowing

Now we get to an important concept.

You can declare a variable with the same name in an inner scope.

```js
let name = "Nayeem";

if (true) {
    let name = "Rahim";

    console.log(name);
}

console.log(name);
```

Output:

```text
Rahim
Nayeem
```

What's happening?

The inner `name` **shadows** the outer `name`.

Think:

```text
Global:
name = "Nayeem"

    ↓

Block:
name = "Rahim"
```

Inside the block, JavaScript uses the closest `name`.

---

# ⭐ 1️⃣4️⃣ Shadowing With Functions

```js
let message = "Global";

function test() {
    let message = "Local";

    console.log(message);
}

test();

console.log(message);
```

Output:

```text
Local
Global
```

Inside the function, JavaScript finds the local variable first.

---

# 1️⃣5️⃣ `var` and Shadowing

Here's an interesting difference.

```js
var x = 10;

if (true) {
    var x = 20;
}

console.log(x);
```

Output:

```text
20
```

Because `var` is not block-scoped.

Both declarations refer to the same function/global-scoped variable.

Compare:

```js
let x = 10;

if (true) {
    let x = 20;
}

console.log(x);
```

Output:

```text
10
```

Because the inner `let` creates a separate block-scoped variable.

---

# 🔥 1️⃣6️⃣ Lexical Scope

This is a slightly more advanced concept.

JavaScript uses **lexical scoping**.

That means:

> **A function's accessible variables are determined by where the function is written in the code, not where it is called.**

Example:

```js
let name = "Nayeem";

function greet() {
    console.log(name);
}

function test() {
    let name = "Rahim";

    greet();
}

test();
```

What do you think happens?

Output:

```text
Nayeem
```

Not:

```text
Rahim
```

Why?

Because `greet()` was defined in the global scope.

Its lexical environment is based on **where it was created**, not where `greet()` was called.

This concept becomes extremely important when you learn **closures**.

---

# 1️⃣7️⃣ Scope vs Accessibility

Let's make this very simple.

```js
let name = "Nayeem";

function greet() {
    let message = "Hello";

    console.log(name);    // ✅
    console.log(message); // ✅
}

greet();

console.log(name);       // ✅
console.log(message);    // ❌
```

Why?

| Variable  | Where declared | Accessible            |
| --------- | -------------- | --------------------- |
| `name`    | Global         | Global + inner scopes |
| `message` | Function       | Only inside function  |

---

# 1️⃣8️⃣ `var`, `let`, and `const`

This comparison is worth memorizing.

| Feature                  | `var` | `let` | `const` |
| ------------------------ | ----- | ----- | ------- |
| Function scoped          | ✅     | ✅*    | ✅*      |
| Block scoped             | ❌     | ✅     | ✅       |
| Can reassign             | ✅     | ✅     | ❌       |
| Can redeclare same scope | ✅     | ❌     | ❌       |
| Modern recommendation    | ❌     | ✅     | ✅       |

`*` `let` and `const` are also accessible within their containing function, but their key distinction is that they are **block-scoped**.

---

# ⭐ 1️⃣9️⃣ Temporal Dead Zone (TDZ)

This is an interview-level concept.

Consider:

```js
console.log(age);

let age = 25;
```

You might think:

```text
undefined
```

But that's incorrect.

It throws a:

```text
ReferenceError
```

Why?

Because `let` and `const` variables are in the **Temporal Dead Zone** from the start of their scope until their declaration is executed.

For now, remember:

> **Don't access `let` or `const` before their declaration.**

We'll study TDZ more deeply when we learn **hoisting**.

---

# 2️⃣0️⃣ Real-World Example

Imagine you're building a website:

```js
const appName = "My Website";

function loginUser(username) {
    const message = `Welcome ${username}`;

    if (username) {
        const status = "Logged in";

        console.log(appName);
        console.log(message);
        console.log(status);
    }
}
```

Inside the `if` block, you can access:

```text
appName
message
status
```

because:

```text
status     → current block
message    → outer function
appName    → global
```

That's the scope chain in action.

---

# 🧠 The Golden Rules

If you remember only these, you're in good shape:

### Rule 1

```text
Global variables
↓
Can generally be accessed by inner scopes
```

### Rule 2

```text
Inner variables
↓
Cannot be accessed from outer scopes
```

### Rule 3

```text
let / const → block scoped
var         → function scoped
```

### Rule 4

```text
JavaScript searches:
Current scope
↓
Outer scope
↓
Next outer scope
↓
Global scope
```

### Rule 5

> **Use `const` by default, `let` when reassignment is needed, and generally avoid `var`.**
