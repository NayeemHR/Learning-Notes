Absolutely. You're following a very good learning path. You already understand **variables, data types, operators, conditions, functions, scope, and arrays**.

Now we move to one of the **most important JavaScript concepts: Objects**.

# 🧠 Lesson 10: Objects & Properties in JavaScript

If an **array** is useful for storing a list of values:

```js
let fruits = ["Apple", "Banana", "Mango"];
```

an **object** is useful for storing information about a particular thing.

For example, a user:

```js
let user = {
    name: "Nayeem",
    age: 25,
    country: "Bangladesh"
};
```

Think of it like this:

```text
Object: user

┌─────────────────────────────┐
│ name    → "Nayeem"          │
│ age     → 25                │
│ country → "Bangladesh"      │
└─────────────────────────────┘
```

Each piece of information is called a **property**.

---

# 1️⃣ What Is an Object?

An **object is a collection of related data and functionality stored as key-value pairs.**

Example:

```js
const user = {
    name: "Nayeem",
    age: 25,
    isDeveloper: true
};
```

Here:

```text
name         → key
"Nayeem"     → value

age          → key
25           → value

isDeveloper  → key
true         → value
```

Together:

```text
key + value = property
```

So:

```js
name: "Nayeem"
```

is a property.

---

# 2️⃣ Creating an Object

The most common way is with curly braces:

```js
const person = {
    name: "Nayeem",
    age: 25,
    city: "Dhaka"
};
```

You can have:

* Strings
* Numbers
* Booleans
* Arrays
* Other objects
* Functions

inside an object.

For example:

```js
const user = {
    name: "Nayeem",
    age: 25,
    skills: ["HTML", "CSS", "JavaScript"],
    isActive: true
};
```

---

# 3️⃣ Accessing Properties

There are two main ways.

## Dot notation

```js
const user = {
    name: "Nayeem",
    age: 25
};

console.log(user.name);
```

Output:

```text
Nayeem
```

And:

```js
console.log(user.age);
```

Output:

```text
25
```

This is the most common approach.

---

# 4️⃣ Bracket Notation

You can also use brackets:

```js
console.log(user["name"]);
```

Output:

```text
Nayeem
```

And:

```js
console.log(user["age"]);
```

Output:

```text
25
```

So:

```js
user.name
```

and:

```js
user["name"]
```

access the same property.

---

# ⭐ 5️⃣ Dot Notation vs Bracket Notation

This is important.

Suppose:

```js
const user = {
    name: "Nayeem"
};
```

Dot notation:

```js
user.name
```

Bracket notation:

```js
user["name"]
```

Both work.

But bracket notation becomes especially useful when the property name comes from a variable.

```js
const user = {
    name: "Nayeem",
    age: 25
};

let property = "name";

console.log(user[property]);
```

Output:

```text
Nayeem
```

Notice:

```js
user[property]
```

works.

But:

```js
user.property
```

would look for a property literally named `"property"`.

This distinction is **very important**.

---

# 6️⃣ Adding a New Property

Objects are mutable, so you can add properties.

```js
const user = {
    name: "Nayeem"
};

user.age = 25;

console.log(user);
```

Now:

```js
{
    name: "Nayeem",
    age: 25
}
```

You can also use brackets:

```js
user["country"] = "Bangladesh";
```

Now:

```js
{
    name: "Nayeem",
    age: 25,
    country: "Bangladesh"
}
```

---

# 7️⃣ Updating a Property

Suppose:

```js
const user = {
    name: "Nayeem",
    age: 25
};
```

You can change the age:

```js
user.age = 26;
```

Now:

```js
console.log(user.age);
```

Output:

```text
26
```

### Important question

We used:

```js
const user = {...};
```

but changed:

```js
user.age = 26;
```

Is that allowed?

**Yes.**

Because `const` prevents **reassignment of the variable**, not modification of the object's contents.

This is a very important concept.

---

# 🔥 8️⃣ `const` Object Does NOT Mean Immutable

Consider:

```js
const user = {
    name: "Nayeem"
};
```

This is allowed:

```js
user.name = "Rahim";
```

Because we're modifying the object's property.

But this is not:

```js
user = {
    name: "Rahim"
};
```

That attempts to assign a completely new object to the `user` variable.

So:

```text
const object
     ↓
Can modify properties?       ✅ Yes
Can reassign the variable?   ❌ No
```

We'll later discuss how to make objects immutable in more advanced JavaScript.

---

# 9️⃣ Deleting a Property

You can remove a property using `delete`.

```js
const user = {
    name: "Nayeem",
    age: 25,
    city: "Dhaka"
};

delete user.city;

console.log(user);
```

Result:

```js
{
    name: "Nayeem",
    age: 25
}
```

The `city` property has been removed.

---

# 🔟 Checking Whether a Property Exists

You can use the `in` operator:

```js
const user = {
    name: "Nayeem",
    age: 25
};

console.log("name" in user);
```

Result:

```text
true
```

And:

```js
console.log("email" in user);
```

Result:

```text
false
```

# 1️⃣1️⃣ Object Methods

An object can also contain functions.

When a function belongs to an object, we commonly call it a **method**.

Example:

```js
const user = {
    name: "Nayeem",

    greet: function () {
        console.log("Hello!");
    }
};
```

Now:

```js
user.greet();
```

Output:

```text
Hello!
```

Here:

```js
greet
```

is a method.

---

# ⭐ 1️⃣2️⃣ Shorthand Method Syntax

Modern JavaScript allows:

```js
const user = {
    name: "Nayeem",

    greet() {
        console.log("Hello!");
    }
};
```

This is cleaner than:

```js
greet: function () {
    console.log("Hello!");
}
```

You'll see this frequently in modern JavaScript.

---

# 1️⃣3️⃣ Object Methods Can Use Object Properties

Here's where things get interesting.

```js
const user = {
    name: "Nayeem",

    greet() {
        console.log(`Hello ${this.name}`);
    }
};

user.greet();
```

Output:

```text
Hello Nayeem
```

What is:

```js
this.name
```

?

`this` refers to the object in this method call:

```js
user.greet();
```

So:

```js
this.name
```

means approximately:

```js
user.name
```

We'll study `this` separately because it deserves its own lesson.

---

# 1️⃣4️⃣ Nested Objects

Objects can contain other objects.

```js
const user = {
    name: "Nayeem",

    address: {
        city: "Dhaka",
        country: "Bangladesh"
    }
};
```

To access the city:

```js
console.log(user.address.city);
```

Output:

```text
Dhaka
```

Think:

```text
user
 │
 ├── name
 │
 └── address
      │
      ├── city
      └── country
```

Imagine you get user data from an API:

To access Rahim's age:

Output:

```text

You'll see this structure **everywhere** in web development.

# 1️⃣6️⃣ Arrays Inside Objects

Access the first skill:

Access JavaScript:

```

Output:

# 🔥 1️⃣7️⃣ Object Destructuring

Now we're entering modern JavaScript.

Instead of:

```js
const user = {
    name: "Nayeem",
    age: 25
};

const name = user.name;
const age = user.age;
```

You can use **destructuring**:

```js
const { name, age } = user;

console.log(name);
console.log(age);
```

Output:

```text
Nayeem
25
```

This is called **object destructuring**.

You'll use this constantly in modern JavaScript and React.

---

# 1️⃣8️⃣ Renaming During Destructuring

Suppose:

```js
const user = {
    name: "Nayeem",
    age: 25
};
```

You can rename:

```js
const { name: userName } = user;

console.log(userName);
```

Output:

```text
Nayeem
```

Here:

```text
name     → actual property
userName → local variable
```

---

# 1️⃣9️⃣ Default Values in Destructuring

Suppose the object doesn't contain `country`:

```js
const user = {
    name: "Nayeem"
};

const { country = "Bangladesh" } = user;

console.log(country);
```

Output:

```text
Bangladesh
```

This is useful when dealing with data where some properties might be missing.

# 2️⃣0️⃣ Object Property Shorthand

Suppose you have:

```js
const name = "Nayeem";
const age = 25;
```

You could create:

```js
const user = {
    name: name,
    age: age
};
```

But modern JavaScript lets you write:

```js
const user = {
    name,
    age
};
```

JavaScript understands:

```text
name: name
age: age
```

automatically.

This is called **property shorthand**.

---

# ⭐ 2️⃣1️⃣ Computed Property Names

You can dynamically create property names.

```js
const property = "name";

const user = {
    [property]: "Nayeem"
};

console.log(user.name);
```

Output:

```text
Nayeem
```

The brackets:

```js
[property]
```

tell JavaScript to evaluate the variable and use its value as the property name.

---

# 2️⃣2️⃣ Object.keys()

Sometimes you need all property names.

```js
const user = {
    name: "Nayeem",
    age: 25,
    country: "Bangladesh"
};

console.log(Object.keys(user));
```

Result:

```js
["name", "age", "country"]
```

---

# 2️⃣3️⃣ Object.values()

Get all values:

```js
console.log(Object.values(user));
```

Result:

```js
["Nayeem", 25, "Bangladesh"]
```

---

# 2️⃣4️⃣ Object.entries()

Get both keys and values:

```js
console.log(Object.entries(user));
```

Result:

```js
[
    ["name", "Nayeem"],
    ["age", 25],
    ["country", "Bangladesh"]
]
```

This is useful when you need to loop through an object's properties.

---

# 2️⃣5️⃣ Looping Through an Object

You can use `for...in`:

```js
const user = {
    name: "Nayeem",
    age: 25,
    country: "Bangladesh"
};

for (let key in user) {
    console.log(key);
}
```

Output:

```text
name
age
country
```

You can get the value with:

```js
for (let key in user) {
    console.log(user[key]);
}
```

Output:

```text
Nayeem
25
Bangladesh
```

And both together:

```js
for (let key in user) {
    console.log(key, user[key]);
}
```

---

# 🧠 2️⃣6️⃣ Why `user[key]` Instead of `user.key`?

This is a very important concept.

```js
const user = {
    name: "Nayeem",
    age: 25
};

const key = "name";

console.log(user[key]);
```

→ `"Nayeem"`

But:

```js
console.log(user.key);
```

→ `undefined`

Why?

Because:

```js
user.key
```

means:

> "Give me the property literally named `key`."

While:

```js
user[key]
```

means:

> "Evaluate the variable `key`, then use its value as the property name."

This is why bracket notation is essential when working with **dynamic property names**.

---

# 🔥 2️⃣7️⃣ Object Spread

Just like arrays, objects support the spread operator.

```js
const user = {
    name: "Nayeem",
    age: 25
};

const updatedUser = {
    ...user,
    age: 26
};

console.log(updatedUser);
```

Result:

```js
{
    name: "Nayeem",
    age: 26
}
```

This creates a **new object** rather than modifying the original.

This pattern is extremely important in modern JavaScript and React.

---

# 2️⃣8️⃣ Combining Objects

```js
const personalInfo = {
    name: "Nayeem",
    age: 25
};

const location = {
    city: "Dhaka",
    country: "Bangladesh"
};

const user = {
    ...personalInfo,
    ...location
};
```

Result:

```js
{
    name: "Nayeem",
    age: 25,
    city: "Dhaka",
    country: "Bangladesh"
}
```

---

# ⭐ 2️⃣9️⃣ Object References

Here's an important concept.

Consider:

```js
const user1 = {
    name: "Nayeem"
};

const user2 = user1;

user2.name = "Rahim";

console.log(user1.name);
```

What do you think?

It prints:

```text
Rahim
```

Why?

Because `user1` and `user2` refer to the **same object**.

Think:

```text
user1 ──────┐
            ↓
        { name: "Nayeem" }
            ↑
user2 ──────┘
```

Changing through `user2` also changes what `user1` sees.

This is related to JavaScript's **reference behavior** and is very important when working with objects.

---

# 3️⃣0️⃣ Comparing Objects

Here's another common interview trap:

```js
const user1 = {
    name: "Nayeem"
};

const user2 = {
    name: "Nayeem"
};

console.log(user1 === user2);
```

Result:

```text
false
```

Why?

Even though they contain the same data, they're **two different object references**.

Compare primitives:

```js
console.log("Nayeem" === "Nayeem");
```

→ `true`

Objects are compared by reference, not by their contents.

```js
// Create
const user = {
    name: "Nayeem",
    age: 25
};

// Access
user.name;
user["name"];

// Add
user.country = "Bangladesh";

// Update
user.age = 26;

// Delete
delete user.country;

// Check property
"name" in user;

// Keys
Object.keys(user);

// Values
Object.values(user);

// Entries
Object.entries(user);

// Destructuring
const { name, age } = user;

// Spread
const newUser = { ...user };
```
