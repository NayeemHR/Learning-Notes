# 📦 JavaScript `export` & `import`

## 1. Why do we need `export` and `import`?

Imagine you have a large project:

```text
project/
│
├── products.js
├── cart.js
├── users.js
└── app.js
```

Instead of putting everything into one huge JavaScript file, we can split our code into **modules**.

For example:

```js
// products.js
const products = ["Laptop", "Mouse", "Keyboard"];
```

Then use `products` inside another file:

```js
// app.js
console.log(products);
```

❌ This won't work automatically.

We need:

```text
products.js
     ↓
   export
     ↓
   import
     ↓
app.js
```

### Mental model

Think of:

* `export` → **"Make this available outside this file."**
* `import` → **"Bring that thing into this file."**

---

# 2. Named Export

Let's start with the most common type.

### `products.js`

```js
export const products = ["Laptop", "Mouse", "Keyboard"];
```

Now another file can import it.

### `app.js`

```js
import { products } from "./products.js";

console.log(products);
```

Output:

```text
["Laptop", "Mouse", "Keyboard"]
```

Notice the `{ }`.

```js
import { products } from "./products.js";
       ^^^^^^^^
```

These indicate that we're importing a **named export**.

---

# 3. Export Multiple Things

You can export multiple variables/functions from the same file.

### `math.js`

```js
export const PI = 3.1416;

export function add(a, b) {
    return a + b;
}

export function subtract(a, b) {
    return a - b;
}
```

Then:

### `app.js`

```js
import { PI, add, subtract } from "./math.js";

console.log(PI);
console.log(add(10, 5));
console.log(subtract(10, 5));
```

Output:

```text
3.1416
15
5
```

---

# 4. Export at the Bottom

You don't have to put `export` directly in front of every declaration.

You can do:

```js
const PI = 3.1416;

function add(a, b) {
    return a + b;
}

function subtract(a, b) {
    return a - b;
}

export { PI, add, subtract };
```

Then:

```js
import { PI, add, subtract } from "./math.js";
```

Both approaches are valid.

---

# 5. Renaming an Import

Suppose you have:

```js
// user.js

export const name = "Nayeem";
```

You can rename it while importing:

```js
import { name as userName } from "./user.js";

console.log(userName);
```

Here:

```text
name      → original exported name
userName  → local name
```

This is useful when there could be naming conflicts.

---

# 6. Default Export ⭐

Now we have another important concept:

**default export**

### `user.js`

```js
const user = {
    name: "Nayeem",
    age: 25
};

export default user;
```

Import it:

```js
import user from "./user.js";

console.log(user.name);
```

Notice something important:

### Named export

```js
export const user = {};
```

Import:

```js
import { user } from "./user.js";
```

### Default export

```js
export default user;
```

Import:

```js
import user from "./user.js";
```

**No `{}` for default imports.**

---

# 7. Default Export Can Be Renamed

This is an important difference.

If you have:

```js
// user.js

export default {
    name: "Nayeem",
    age: 25
};
```

You can import it as:

```js
import user from "./user.js";
```

Or:

```js
import currentUser from "./user.js";
```

Or:

```js
import person from "./user.js";
```

All are valid.

Because it's the **default export**.

---

# 8. Can a File Have Both?

Yes! ⭐

Example:

### `user.js`

```js
export const name = "Nayeem";

export const age = 25;

const user = {
    name,
    age
};

export default user;
```

Then:

```js
import user, { name, age } from "./user.js";

console.log(user);
console.log(name);
console.log(age);
```

The structure is:

```text
default export
      ↓
    user

named exports
      ↓
   name, age
```

---

# 9. Import Everything

You can import all named exports using `*`.

### `math.js`

```js
export const PI = 3.1416;

export function add(a, b) {
    return a + b;
}

export function subtract(a, b) {
    return a - b;
}
```

### `app.js`

```js
import * as math from "./math.js";

console.log(math.PI);
console.log(math.add(10, 5));
console.log(math.subtract(10, 5));
```

Here:

```js
math
```

becomes an object-like namespace containing the exports.

Think:

```js
math = {
    PI,
    add,
    subtract
}
```

# 10. Real-World Example

Imagine a shopping website.

### `products.js`

```js
export const products = [
    {
        id: 1,
        name: "Laptop",
        price: 80000
    },
    {
        id: 2,
        name: "Mouse",
        price: 1500
    }
];
```

### `cart.js`

```js
export function addToCart(cart, product) {
    return [...cart, product];
}

export function calculateTotal(cart) {
    return cart.reduce((total, product) => {
        return total + product.price;
    }, 0);
}
```

### `app.js`

```js
import { products } from "./products.js";

import {
    addToCart,
    calculateTotal
} from "./cart.js";

let cart = [];

cart = addToCart(cart, products[0]);

console.log(calculateTotal(cart));
```

This is how real applications are organized.

```text
products.js
    │
    │ export
    ↓
  app.js
    ↑
    │ import
    │
cart.js
```

# 11. Named vs Default Export

This is **very important for interviews**.

| Named Export              | Default Export               |
| ------------------------- | ---------------------------- |
| `export const user = {}`  | `export default user`        |
| Import uses `{}`          | Import doesn't use `{}`      |
| Multiple allowed          | One default per module       |
| Name generally must match | Import name can be different |

Example:

### Named

```js
export const add = () => {};
```

```js
import { add } from "./math.js";
```

### Default

```js
export default add;
```

```js
import anything from "./math.js";
```

---

# 12. One Important Rule

A module can have:

```text
0 or more named exports
+
maximum 1 default export
```

For example:

```js
export const a = 10;
export const b = 20;
export const c = 30;

export default function hello() {
    console.log("Hello");
}
```

Valid ✅

But:

```js
export default a;
export default b;
```

❌ Invalid.

A module can only have **one default export**.

---

# 13. How Does JavaScript Know It's a Module?

In browsers, your HTML usually needs:

```html
<script type="module" src="./app.js"></script>
```

The `type="module"` tells the browser:

> "Treat this JavaScript file as an ES module."

Then `import`/`export` can be used.

# 🧠 Interview Mental Model

Remember this:

```text
export = send out
import = bring in
```

And:

```js
export const x = 10;
```

means:

> "x is available for other modules."

While:

```js
import { x } from "./file.js";
```

means:

> "Bring the named export x from that module."
